# 0. 읽는 순서와 주장 범위

이 노트의 대상은 POSTECH 학생의 관심에서 연구실을 발견하고, 연구실을 이해하거나 연구에 준비하는 데 도움이 되는 과목을 설명하는 3분커리 서비스다. 질문은 두 가지다. 첫째, 연구실과 과목의 어떤 정보가 검색·추천 점수에 들어가야 하는가. 둘째, 원자료의 사람·연락처·위치·평가 방식처럼 화면 표시나 운영에 필요한 정보가 **임베딩 입력에도** 들어가야 하는가. 두 번째 질문에 대한 정량 답은 임베딩 필드 추가 실험의 새 판정 결과에만 근거한다. 현재 서비스 구현과 목표 스키마, 원본 데이터와 파생 임베딩 뷰를 혼동하지 않는다.

여기서 `lab`은 원본 `final_labs.jsonl`의 교수별 행을 가리킨다. 서로 다른 교수가 같은 소개·URL·논문을 공유할 수 있어 교수 행을 독립 표본으로 세지 않는다. `course`는 `final_courses.jsonl`의 개설/코드 행이다. 같은 제목·교육본문의 여러 코드도 확정된 동일 과목으로 자동 합치지 않는다.

**판정 상태 표기:** 확인적이라는 말은 사전 고정한 한 대비와 이전 성과를 사용하지 않은 평가 집합에 한정한다. 탐색적이라는 말은 비교할 수는 있지만 제품 성능이나 일반화의 확증에 쓸 수 없다는 뜻이다. Luna A와 B는 서로 다른 모델 심사위원이며 점수를 평균해 학생·교수의 정답으로 만들지 않는다. 두 심사위원이 실험 설계와 결과 해석의 제한 범위에 모두 동의해야 이 노트의 결론으로 채택한다.

# 1. 서비스 문제를 검색 문제로 바꾸기

## 1.1 두 종류의 관계

학생의 자연어 관심 → 연구실 발견과, 연구실의 연구 → 준비 과목 연결은 목적 함수가 다르다. `studies(domain/problem/material)`은 “이 연구실이 무엇을 연구하는가”를 설명한다. `uses/develops(method/tool)`와 과목의 `teaches(method/tool)`가 같은 뜻일 때에는 “이 과목이 연구를 준비하는 데 왜 도움이 될 수 있는가”의 직접 근거가 된다. 단순한 주제 단어의 공통 출현은 준비 관계의 충분 조건이 아니다. 실험에서 *logic*이 논문 작성 논리와 회로 논리, *manipulation*이 테라헤르츠파 제어와 로봇 조작을 잘못 묶은 사례가 있었다. 원문 주변 문맥과 행동의 주체·대상, 개념의 뜻 ID가 필요하다.

## 1.2 저장, 임베딩, 노출은 다른 결정

원본의 행정·인물·주소 정보를 지워야 한다는 결론은 아니다. 연락처는 출처 확인이나 사용자 화면에, 학과는 필터나 그룹 분석에, 교수와 연구실의 소속은 식별자에 필요할 수 있다. 임베딩 입력은 별도 파생 뷰로 관리한다. 후보 검색용 텍스트, 직접 준비 관계 판정용 원문 span, 화면 표시용 메타데이터는 서로 다른 컬럼과 접근 경로를 갖는다. 특히 대표 논문이 목록에 수록됐다는 사실은 그 연구실의 현재 기술 사용을 보증하지 않는다.

# 2. 선행 연구와 벤치마크에서 가져온 방법

| 자료 | 원 연구의 역할 | 본 서비스에서 가져온 방법 | 가져오지 않은 주장 |
|---|---|---|---|
| [BEIR](https://arxiv.org/abs/2104.08663) | 서로 다른 검색 도메인에서 lexical, dense, reranker 등을 공통 평가틀로 비교 | 같은 후보군·질의·라벨·측정 단위로 필드 변형 비교 | BEIR 점수를 POSTECH 연구실 추천 점수로 이전하지 않음 |
| [BGE-M3](https://arxiv.org/abs/2402.03216) | 다국어, dense/sparse/multi-vector, 짧은 문장과 긴 입력을 포괄하는 임베딩 모델 | 한국어·영어가 섞인 과목/논문 청크를 같은 모델 개정과 토큰 상한으로 계산 | 긴 입력을 지원하므로 전체 크롤링을 넣어야 한다는 뜻이 아님 |
| [Multi-view Content-aware Indexing](https://arxiv.org/abs/2404.15103) | 긴 문서의 고정 청크가 중요 내용을 잃거나 무관한 내용을 포함할 수 있음을 연구 | 청크와 필드의 구성 자체를 독립 변수로 등록 | 원 논문의 성능 수치를 본 데이터에 대입하지 않음 |
| [TREC Deep Learning](https://trec.nist.gov/data/deep2023.html) | 다단계 관련도 판정과 nDCG 등 검색 평가의 공개 예시 | 0/1/2 관련도, 미판정과 불충분의 구분, 노출 순위별 분석 | 기존 단일 평가자의 점수를 절대 정답으로 취급하지 않음 |

생성형 언어 모델의 긴 프롬프트에서 중간 정보 활용이 약해질 수 있다는 [Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/)도 참고했다. 하지만 그 연구는 본 BGE 임베딩 필드 제거 효과를 직접 검증하지 않는다. 따라서 크롤링 잡음 가설의 동기 이상으로 쓰지 않는다.

## 3.2 무엇이 행정·혼합 정보인가

새 필드 감사는 보류 180교수 행의 `research_intro` 길이 중앙값 1,966자, 95백분위 12,509자를 확인했다. 단순 정규식 표지가 잡힌 행은 오피스·위치 16/180, 사람·학생 77/180, 뉴스 47/180, 연락 72/180이었다. 이는 “해당 단어가 있다”는 **탐지 건수**이며 그 문단이 모두 무관하거나 전체 글의 해당 비율이 얼마라는 판정은 아니다. 연구실 `lab_mates` 구조 필드가 비어 있지 않은 행은 6/180, `admission` 39/180, `centers` 4/180이었다. 따라서 대학원생 수·오피스 위치가 임베딩을 얼마나 손상시키는지 직접 인과 추정할 수 있는 구조화 표본은 매우 부족하다.

전체 1,316과목에서는 `description` 1,281행, `Lecture progress plan` 1,109행, `grading` 1,096행, `course_operation` 880행, `other_info` 471행, `prerequisites` 1,015행, `textbooks` 540행, `references` 890행이 비어 있지 않았다. 평가·운영 텍스트에 교수/조교 연락처가 섞일 수 있으므로 임베딩용 파생 뷰와 화면 원자료를 나눠야 한다.

## 3.3 새로운 필드 비교의 독립 집합

2026-10-16 필드 비교에서는 137개 보류 구성요소·180행 모두의 GPU 순위를 만들되, 이전 평가의 112개 구성요소·136행은 탐색 구조 지표로만 사용한다. 남은 25개 구성요소·44행 중 7개·16행은 과거 `previous_split=test`였음을 두 Luna 심사에서 발견했다. **정말로 미사용인 18개 구성요소·28행**만 새 관련도 판정과 확인적 짝 비교에 쓴다. 이는 과거 라벨과 별개이지만 평가자가 원문을 전혀 본 적 없다는 완전 맹검은 아니다. 18/106 미사용 보류 프레임에서 한 이항 비율의 최악 95% 보정 폭조차 약 ±21%p이므로 작은 차이를 검출하기 어렵다.

# 4. 목표 데이터 계약과 임베딩 뷰

기존 `FINAL_DATASET_SCHEMA_V2_DECISION.md`는 두 Luna가 수용한 목표 계약이며 현행 앱 구현이 아니다. 중심 레코드는 `course`/`course_offering`, `advisor`/`lab`/`lab_membership`, `paper`/`paper_lab_evidence`, `source_evidence`, `concept_sense`/`sense_mapping`, `assertion`, `lab_discovery_evidence`, `recommendation_evidence`, 파생 `query_intent`다.

| 계약 부분 | 담을 정보 | 규칙에서 지킬 조건 |
|---|---|---|
| 원본 엔터티 | 안정 ID, 공급자 코드, 표시 메타데이터, 값 상태 | 빈 값·확인 안 함·명시적 없음과 0점을 구분 |
| 원문 근거 | 출처 파일 SHA·행·중첩 경로·문자 `[start,end)`·소유 claim | 추천 이유가 실제 원문으로 돌아갈 수 있어야 함 |
| 연구 주장 | `lab` 자신 또는 `paper_listing`이 `uses/develops/studies`한 개념 뜻 | 논문 수록을 연구실 현재 역량으로 자동 승격 금지 |
| 과목 주장 | `course_offering`이 `teaches`한 방법·도구 뜻 | 제목·강의목표 복사를 독립 근거로 두 번 세지 않음 |
| 발견 연결 | `studies(domain/problem/material)`와 관심 뜻 | 과목 준비 점수로 자동 승격 금지 |
| 준비 연결 | 연구측 `uses/develops(method/tool)` ↔ 과목측 `teaches`가 같은 검토된 뜻 | 불일치·다의어·출처 부족은 `insufficient_evidence` 보류 |
| 점수 | 검색 점수와 규칙 조정·중복 조정의 버전별 구성 | 검증 전 가중치나 불충분을 임의 0점으로 확정하지 않음 |

**제안 파생 뷰:** `embedding_view`는 `(view_id, entity_kind, entity_id, purpose, profile_version, chunk_id, source_evidence_ids, field_paths, text_sha256, token_limit, inclusion_reason, exclusion_policy)`를 가진다. `purpose`는 `lab_discovery`, `course_preparation`, `course_search`처럼 검색 목적을 구분한다. 인코딩 벡터 저장은 `(chunk_id, model_revision, tokenizer_version, max_tokens, normalized, vector_ref, computed_at)`으로 별도 관리한다. 원본의 사람이름·오피스·연락처는 필요하다면 원본/표시 영역에 남기되 **임베딩 뷰의 기본 포함 대상은 아니다**. 필드 포함 여부는 아래 정량 비교에서 확인된 범위 안에서만 정책으로 굳힌다. 이 뷰는 제안이며 아직 앱에 구현되지 않았다.

규칙 처리 순서는 질의의 긍정/부정 구절과 모호성 분리 → 넓은 연구실 후보 검색 → 연구실 발견 주장 확인 → 연구측 방법·도구와 과목의 가르치는 내용 같은 뜻 확인 → 원문 근거·행동 주체·출처 상태 검사 → 연결 가능한 과목만 설명 → 검증된 순위기 점수와 중복 관리다. `logic` 등의 다의어는 검토된 뜻 매핑 없이 자동 연결하지 않는다. 빈 결과를 피하려고 근거 없는 준비 과목 문장을 생성하지 않는다.

### 6.4.1 셔플된 운영 청크의 구조 보조 분석

이 보조 분석은 **순위 안정성만** 본다. 셔플 상위 노출은 새 327쌍 판정 풀 밖의 쌍을 포함하므로 관련도 품질 수치를 계산하지 않았다. 실제 메타데이터의 내용이 유익한지, 청크 수 증가가 해로운지 이 순위 비교만으로 인과 분해할 수 없다.

# 7. 합의 기준과 후속 실험

기존 최종 JSONL 실험은 두 Luna가 각각 특정 범위의 기술 결과만 수용했다. 새 필드 실험 설계에서는 A가 과거 112개 표본 재사용을 확인적 실험으로 부를 수 없다는 문제를 찾아, 미사용 표본만 확인 집합으로 바꿨다. 추가 교차 검사에서 남은 25개 중 7개가 과거 시험임을 A가 발견했고 B도 재검사 후 오판을 수정했다. 결과 단계에서는 A와 B가 각자 원시 점수·공통 순위·방법키·분석 코드를 독립 검산해 주효과와 제한된 해석을 수용했다. A는 중복 점유 지표 누락을 지적했고, 이를 분석 코드와 결과에 보충했다. A의 최초 중복 **행** 집계는 중복 그룹 수를 세어 과다했으며 재검사에서 12/12/12/5/13행으로 정정했다. B는 동일 본문 이종 점수를 지적했고 A에도 같은 검사를 적용해 6그룹의 불일치를 찾았다. 원시 평정을 고치지 않고 사후 민감도를 공개했다. 따라서 두 모델의 “동의”는 단순 과반이 아니라 **서로 독립적으로 원자료·프레임·분석을 확인하고 같은 제한 문장에 도달하는 과정**이다. 결과가 다르면 평균으로 합의한 척하지 않고 불일치를 남긴다.

실서비스 적용에는 다음 검증이 더 필요하다. 연구실 발견 질의에 대한 필드 ablation, 실제 학생이 작성한 질의와 도움 판단, 학과·분야별 신호 손실, 운영 메타데이터 자체가 유효한 연구 신호인 경우의 별도 판정, 개념 뜻/주장 추출기의 정확성, 중복 코드 검토, 새 원자료의 갱신과 교수별 연구실 동일성 검토다. 과거 `bge_m3`의 cross-encoder 재순위·절대 컷오프·전체 과목 회수율과 자유 LLM 생성은 이번 새 데이터셋에서 확인되지 않았다.

# 부록 A. 실험별 재현 카드

## A.1 정보량과 누수 통제

`audit_complete_subset.py`가 정보량 조건을 원본 행에 적용해 적격 941/203을 기록한다. 조건은 정보가 충분한 평가 프레임을 만들기 위한 작동상 기준이지 수업 내용과 연구 내용의 진실성 검증은 아니다. `make_rich_split.py`는 교수별 행에서 동일하거나 공유된 소개·URL·논문 근거를 구성요소로 묶어, 같은 연구실 페이지가 개발과 보류 양쪽에 들어가는 것을 막는다. `rich_split_v1.json`에 개발 19구성요소/23행, 보류 137구성요소/180행이 저장된다. 표본을 교수 행 단위로 재표본하면 공유 소개의 복제를 서로 독립인 관측처럼 취급하게 되므로, 신뢰구간 재표본은 구성요소 단위다.

정보량이 적어 제외된 연구실과 과목의 추천 품질에는 이 결과를 외삽하지 않는다. 적격 프레임 안에서도 `paper_listing`에는 제목·초록을 통해 많은 텍스트가 있으나 실제 연구실의 현재 장비·방법을 확인한 것은 아니다. 원문 출처가 동일한 두 주장, 강의 설명과 학습목표의 동일 문장, 복수 코드의 동일 본문을 독립 근거로 누적하지 않는다.

## A.2 관계 규칙 실험

`PREREG_RELATIONS.md`, 동결 `frozen_relation_design_v15.json`, `holdout_relations_v15/`, `holdout_relevance_v1/`가 설계·순위·판정·분석을 잇는다. v15는 941개 공통 후보에서 180교수 행을 처리하고, 5,478개 후보 주장의 원문 위치를 확인했다. 보류 판정은 112구성요소/136행의 상위 노출 합집합 910쌍이다. B0는 넓은 개념 확장에 기반해 과목 후보를 주고, B1은 출처가 직접 잇는 연구 방법·도구 관계를 제한적으로 사용한다. 평가의 고정 다섯 칸 효용은 목록이 비면 빈칸을 0으로 남겨 과도하게 짧은 목록을 보상하지 않는다.

B1의 첫 다섯 칸이 비는 79/136행과 구성요소 빈 목록 61.6%는 두 통계 단위가 다르다. A와 B의 효용 차이는 각각 −0.421, −0.410이며 두 구간이 음수이므로 직접 연결만으로 서비스 목록을 채우는 것은 이 프레임에서 불리했다. 하지만 직접 연결이 있는 특정 쌍의 설명 가치까지 부정하는 결과는 아니다. 스키마에는 `direct_verified`, `candidate_unverified`, `insufficient_evidence`를 구분해, 좁은 규칙을 목록 생성의 단독 관문 대신 강한 근거로 사용한다.

## A.3 임베딩과 규칙 가산

`PREREG_BGE_RICH_TOP1.md`, `bge_rich_kaggle.ipynb`, GPU 출력 `bge_rich_v1/`, `bge_top1_relevance_v1/`을 연결하면 상위 1개 결과를 재현할 수 있다. 같은 BGE-M3 개정, 같은 256토큰 조건에서 dense 점수에 동결 B1 관계 존재 보너스 +0.08을 적용했다. 136행 중 37행의 첫 과목이 달라졌지만, 구성요소 효용 차이는 A −0.018(−0.058~+0.022), B −0.006(−0.043~+0.032)으로 두 판정에서 확실한 개선을 보이지 않았다.

`PREREG_BGE_RICH_TOP5_EXTENSION.md`, `bge_top5_extension_v1/`의 확장은 그 상위 1개 결과를 본 뒤 정한 사후 분석이다. 상위 5개에 새로 필요한 562쌍을 두 Luna가 모두 판정했다. 첫 다섯 칸 전체를 채우면 차이가 A +0.016, B +0.003으로 방향은 양수지만 두 구간 모두 0을 지난다. 새 쌍의 완전 일치 58.2%, 극단 불일치 48/562를 고려하면 한 판정자만의 보조 지표 개선으로 정책을 바꿀 근거가 부족하다. 이 평가의 최대 범위는 판정 합집합 내 노출 품질이다. 전체 941개 후보에서 관련 과목을 얼마나 놓쳤는지, cross-encoder 재순위나 절대 cutoff가 어떤 효과를 낼지는 이 결과에 없다.

## A.4 질의 해석

`PREREG_QUERY_RICH.md`, `query_rich_v3/`은 작성 질의 60개에서 전체 문자열을 함께 처리하는 Q0과 선호·회피 구절을 분리하는 Q1을 비교한다. 두 Luna는 433개의 연구실–질의 쌍을 판정했다. 부정이 명시된 30질의에서 관련 항목 비율 변화가 A +8.7%p, B +6.7%p였으나 절대 수준은 A 17.3%, B 19.3%다. 질문을 작성한 평가자가 목표 파일을 보았으므로 실제 사용자의 질의 분포와 같은 조건이 아니다. 따라서 `query_intent`에는 긍정·부정 span과 모호성 상태를 별도로 보존하되, 이 실험을 실제 학생 추천 품질의 검증으로 표기하지 않는다.

## A.5 이유 문장과 표시 카드

`PREREG_REASON_RICH.md`, `reason_rich_v2/`는 근거 충분하다고 판정된 27쌍에서 개념형 R0과 출처 인용형 R1을 비교한다. A의 충실도는 44.4% 대 40.7%, B는 둘 다 66.7%다. R1이 짧은 출처 표기를 포함해도 과목의 준비 관계가 원문에서 곧바로 따라오지 않을 수 있다. 과목 근거 54개 중 46개가 제목 span이라서, 정확한 제목 인용과 정확한 준비 이유를 같은 것으로 취급하지 않는다. 이 실험은 자유 생성 LLM에 대한 직접 비교가 아니다.

`PREREG_AB_RICH.md`, `ab_rich_v2/`은 같은 27쌍을 카드 형태로 놓아 R0/R1 중 더 설득력 있는 표시를 택하게 했다. R1 선택은 A 20, B 24였으나 두 심사위원은 학생이 아니라 평가 모델이다. 같은 쌍을 공유하는 카드 간 상관도 있다. 표시 선호는 충실도 점수의 대체물이 아니며 실제 학생 A/B를 실시한 것으로 기록하지 않는다.

## A.6 피드백 관문

`PREREG_FEEDBACK_RICH.md`, `feedback_rich_v3/`은 실제 피드백이 아닌 합성 제거 이벤트를 136행의 다섯 칸 목록에 적용한다. G0은 하나가 제거되면 6위를 올리고 G1은 해당 칸을 비운다. 따라서 외부 후보 유입은 G0 136/136, G1 0/136으로 설계상 정해진다. 6위의 무관 비율은 A 25.5%, B 31.8%이나 핵심 과목 비율도 A 40.0%, B 44.1%다. G1의 짧아진 목록이 실제 사용자에게 더 유익한지, 응답이 얼마나 쌓일지, 한 연구실의 평가를 다른 연구실에 옮길 수 있는지는 미검증이다.

# 부록 B. 새 필드 실험의 측정 정의와 감사 항목

## B.1 비교가 실제로 바꾸는 것

한 연구실과 한 과목 사이의 점수는 모든 연구실 청크와 과목 청크 쌍의 정규화 벡터 내적 중 최댓값이다. `core+lab_admin`은 연구실마다 운영 청크를 한 개 더 허용한다. `core+course_admin`은 과목마다 운영 청크를 한 개 더 허용한다. `core+both_admin`은 양쪽을 더한다. `learning_context`는 핵심 과목에 선수·교재·참고 청크를 더한다. 이 구조는 간단하고 검색 후보 생성에 유용하지만, 추가 청크 한 개만으로 점수가 오를 기회를 얻는다. 운영 청크끼리 학과명이 같아서 높은 점수가 나왔다면 실제 준비 관계를 말해 주는지 별도 원문 검사가 필요하다.

모든 변형은 같은 941과목을 대상으로 하고 각 연구실에서 점수 내림차순, 동점이면 과목 ID 순으로 정렬한다. top5가 같은 과목으로 남았는지의 `공통 점유`는 위치를 무시한 과목 집합 교집합 크기를 합한 것이다. 순위가 달라져도 관련도가 같은 과목끼리 바뀌면 효용은 같을 수 있다. 반대로 첫 과목이 유지돼도 2~5위가 악화될 수 있다. 그래서 순위 이동은 품질 판정의 대용이 아니다.

## B.2 고정 다섯 칸 효용과 결측

쌍 관련도 `r`은 0, 1, 2다. 한 교수 행의 다섯 자리 효용은 `(r1+r2+r3+r4+r5)/10`으로 0~1에 있다. 공유근거 구성요소 안의 교수 행 효용을 먼저 산술 평균하고, 18개 구성요소의 평균을 낸다. 방법을 비교할 때 한 구성요소의 어느 교수 행에서라도 근거부족 `insufficient_evidence`가 있으면 그 구성요소는 해당 방법의 효용에서 제외한다. 짝차이에는 양 방법 모두 완전한 구성요소만 쓴다. 결측을 0점으로 두면 정보 부족을 무관이라고 오인하므로 금지했다. 제외가 많을 경우 결과가 완전 사례 조건부라는 점도 보고한다.

구성요소 짝차이 18개를 단위로 5,000번 복원추출해 매번 평균을 계산하고 2.5·97.5백분위를 구한다. 확인적 대비는 `core` 효용에서 `both_admin` 효용을 뺀 한 값이다. 두 Luna 각각의 구간 하한이 +0.02보다 커야 운영 필드 제거의 실질적 개선을 인정한다. 편의상 둘을 평균해 한 구간으로 만들지 않는다. 다른 세 대비, 0점 비율, 동일 제목·교육본문 중복, 셔플된 운영 청크는 기전이나 안전성을 보는 보조 분석이다.

## B.3 직접 측정하지 못한 오염

대학원생 수, 오피스 위치, 연락처는 애초에 새 GPU 입력에 들어가지 않았다. 따라서 새 실험의 결과로 “학생 수를 추가하면 품질이 몇 % 하락한다” 또는 “오피스 주소를 넣어도 안전하다”라고 말할 수 없다. `research_intro`의 정규식 표지는 행 수 기준 존재 감지다. 학생 소개에 유용한 연구 분야 설명이 함께 있을 수 있고, 표지가 없는 소개에도 운영 문장이 있을 수 있다. 정제 규칙을 확정할 때에는 문단 단위로 `research_claim`, `people`, `location`, `news`, `contact`를 분리하고, 분류 확신도와 원문 출처를 기록해 다시 시험해야 한다.

### B.3.1 사용자가 든 두 사례의 평가 가능 표본 수

추가 사후 감사 `audit_specific_noise_support.py`는 원문을 복제하지 않고 교수 행 단위 정규식 표지 수만 기록했다. `office`/`room`/`연구실 위치`/`사무실`은 위치 가능성, `대학원생`·`students`·`members` 등과 가까운 숫자는 인원 수 가능성을 뜻한다. 숫자와 단어의 근접은 실제 대학원생 수의 진위를 검증하지 않으므로 **가능 표지**라고 부른다.

| 프레임 | 교수 행 | 오피스 위치 가능 표지 | 숫자 인원 가능 표지 | 값이 있는 `lab_mates` |
|---|---:|---:|---:|---:|
| 새 확인 집합 | 28 | 1 | 2 | 0 |
| 기존 판정 집합 | 136 | 14 | 7 | 2 |
| 과거 시험 노출 집합 | 16 | 1 | 0 | 4 |
| 보류 전체 | 180 | 16 | 9 | 6 |

새 확인 집합에 오피스·인원 표지가 각각 1·2행뿐이고 구조화된 구성원 필드는 비어 있다. 설령 해당 행을 정확히 추출해 GPU에서 별도 인코딩해도 이 표본만으로 개별 필드의 평균 효과나 분야별 효과를 신뢰성 있게 추정할 수 없다. 본 실험에서 지지된 수치는 **운영 메타데이터 묶음의 상위 노출 비교**다. 학생 수와 위치의 직접 효과는 미측정으로 남기며, 별도 수집·문단 판정·새 보류 표본이 생기기 전까지 특정 하락률을 적지 않는다.
