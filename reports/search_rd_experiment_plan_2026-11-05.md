# 3분커리 검색·추천 R&D 실험 계획

작성: 2026-11-05. 상태: 실험 프로토콜 초안. 수치 목표는 출시 판정용 제안이며 현재 성능 측정값이 아니다.

## 결정할 질문

1. 새 정제본 307개 연구실에 대해 현행 사전+BGE-M3 dense 융합보다 나은 검색이 있는가?
2. 좋아함·싫어함 해석, 원문 근거, 과목 연결의 오류를 얼마나 줄일 수 있는가?
3. 품질 이득이 1GB OCI 서버·Kaggle 워커의 지연과 비용을 정당화하는가?

2026-11-05 진단의 20/20은 수정 사례 회귀 검증이다. 실제 질의 관련도 성능은 아직 미측정이다. 옛 4개 학과 질의·정답·벡터는 이 실험에 사용하지 않는다.

## 제품 아키텍처의 단계별 후보

```text
입력 → 의도/긍정·부정 판정 → 넓은 후보 수집 → 근거별 후보 묶기
     → 순위 결정 → 명시적 부정/근거 검사 → 출처가 붙은 설명 → 화면
                  ↘ 해석 불명확/워커 불가: 재질문 또는 사전 검색
```

현행 질의 게이트는 유지한다. 다음으로 원문 문단·대표 논문을 `source_id`, `lab_id`, `span`, `evidence_type`, `snapshot_hash`와 함께 불변 검색 단위로 만든다. 연구실 소개, 논문, 과목 설명을 한 덩어리로 섞지 않는다. 연구실 발견은 `studies` 관계, 준비 과목은 연구실의 `uses/develops`와 과목의 `teaches` 관계로 별도 평가한다. 단어 겹침만으로 관계를 확정하거나 과목을 공식 선수과목으로 표시하지 않는다.

비교할 검색 후보는 다음 순서로 제한한다.

| ID | 검색 방식 | 추가 계산 |
|---|---|---|
| A | 운영 기준선: 현행 사전 검색 + BGE-M3 dense + RRF | 현재 수준 |
| B | BGE-M3 dense 단독 | 동일 워커 모델; 결합 이득 검증 |
| C | 동일 문단에 대한 dense+sparse 후보 합치기 | 워커에서 sparse 산출·저장 추가 |
| D | C의 상위 후보만 multi-vector 또는 별도 재순위화 | 후보 20개 안팎의 추가 GPU 계산 |

BGE-M3는 dense·sparse·multi-vector를 제공하지만 D는 계산 비용이 크므로 C가 개선될 때만 시험한다. 워커가 꺼질 때의 사전 검색은 별도 운영 경로로 측정한다. 새로운 모델이나 RRF 가중치는 개발셋에서만 조정한다.

## 1단계: 판정 자료 제작

- **일반 질의 240개**: 실제 학생이 자발적으로 쓴 질의를 동의·익명화 후 우선 수집한다. 부족한 유형은 별도 작성 질의로 보충하되 출처를 구분한다. 질의 80개는 개발용, 160개는 잠금 시험용. 같은 사람이 쓴 거의 같은 문장이 양쪽에 들어가지 않게 묶음 단위로 분할한다.
- **안전 질의 150개**: 부정·대조·모호한 표현·진로/절차 질문·무의미 입력을 고르게 넣는다. 모델 순위 튜닝에 쓰지 않는 별도 관문이다. 작은 20개 진단셋은 회귀 테스트로만 둔다.
- **과목 연결 질의**: 연구실 후보와 독립적으로 연구실×과목 쌍을 표본 추출한다. 연구실·과목의 상위 후보뿐 아니라 점수 경계와 무관 후보도 포함한다. 교수/연구실 소개와 과목 강의계획의 출처를 함께 판정한다.
- A/B/C 각 방식의 상위 5개 연구실을 합쳐 판정 풀을 만들고 모델·순위를 숨긴다. 연구실 쌍마다 관련도 0~3, 부정 충돌 여부, 인용 근거의 충실도(참/불명/거짓), 출처 종류를 독립 평가자 2명이 판정한다. 불일치와 미판정은 그대로 보존하고 합의 절차를 기록한다.
- 데이터 파일 해시, 임베딩 모델 버전, 정제 코드 버전, 질의 게이트 버전, 판정 기준을 저장한다. 평가자가 정답을 본 뒤 가중치나 입력 청크를 수정하면 잠금 시험셋은 새로 만든다.

상위 5개 3방식의 합집합은 최대 15쌍/질의다. 잠금 시험 160질의에서 최대 2,400쌍, 2인 판정이면 최대 4,800개 평가가 필요하다. 실제 중복이 있으면 줄어든다. 이 노동량을 확보하지 못하면 질의 수를 줄이고 결론의 불확실성을 넓게 보고한다.

## 2단계: 사전 고정 지표와 분석

| 영역 | 주 지표 | 함께 볼 지표 |
|---|---|---|
| 연구실 발견 | 질의별 nDCG@5의 A 대비 짝차이 | Recall@10, 무관 후보@5, 유형별 결과 |
| 질의 안전 | 명시적 부정 충돌률, 절차 질문 오추천률 | 재질문율, 검색 가능 질의의 불필요한 차단률 |
| 설명 | 근거 밖 주장 비율 | 원문 URL/span 정확도, 출처 없는 카드 비율 |
| 과목 | 적합한 과목 P@5 | 거짓 필수/선수 주장 수, 중복 과목 슬롯 |
| 시스템 | 실제 브라우저 P50/P95 첫 결과 시간 | 임베딩 완료율, 사전 검색 후퇴율, 워커 시간/100질의 |

각 질의의 A와 후보 점수 차이를 계산해 **질의 단위로** 재표본추출한 95% 구간을 보고한다. 카드 단위를 독립 표본처럼 취급하지 않는다. 평가자별 점수도 따로 보고하고, 합의 점수만 단독으로 제시하지 않는다. 검색 가능 질의·부정 질의·한국어/영어 혼합·근거가 얇은 연구실을 별도 층으로 보고한다.

160개의 잠금 질의는 작은 효과를 정밀하게 보장하지 않는다. 예를 들어 짝차이 표준편차가 0.20이면 평균 차이의 정규 근사 95% 반폭은 약 0.031이다(1.96×0.20/√160). 실제 변동이 더 크면 구간도 넓다. 안전 질의 150개에서 오류가 0건이어도 이항률의 95% 상한은 약 2%이므로, 0건을 무오류 증명으로 표현하지 않는다.

## 3단계: 운영 실험

동일한 질의를 워커 준비 상태, 워커 콜드 스타트, 워커 부재 상태에서 각각 측정한다. 동시 1/3/5/10개의 **서로 다른** 질의를 3회 이상 반복하고, 질의 순서를 무작위화한다. HTTP 성공과 `mode=embedding` 성공을 분리한다. 서버 RSS·CPU, Kaggle 실행 시간, 대기열 길이, 브라우저 첫 결과 시간을 기록한다. 테스트 계정·IP의 요청 제한은 운영 제한값과 별도로 명시하고 실제 사용자 DB는 사용하지 않는다.

기준 관측값은 준비된 워커의 순차 검색+세션 평균 1.587초, 동시 5건 전부 임베딩, 동시 10건 중 5건만 임베딩, 콜드 첫 질의 128.86초(각 소표본)다. 새 실험의 결과와 비교하되 이 숫자를 서비스 보장값으로 쓰지 않는다.

## 출시 판정 규칙

후보가 잠금 시험셋에서 A 대비 nDCG@5 **절대 +0.05 이상**이고 짝차이 95% 구간 하한이 0보다 클 때 품질 이득으로 간주한다. 동시에 부정 충돌률·근거 밖 주장·절차 질문 오추천을 악화시키지 않아야 한다. 운영 시험에서 동시 5건의 임베딩 완료율이 기준선 아래로 떨어지거나 P95가 기준선보다 20% 넘게 느려지면 우선 최적화 후 재평가한다. 이 문턱은 실험 전에 고정할 제품 기준이며 자연 법칙이나 현재 달성 수치가 아니다.

오프라인 관문을 통과한 후보만 작은 사용자군에 노출한다. 온라인에서는 추천 카드 상세 열람, 후보 저장, 가이드 완료, 사용자가 보고한 관련성·오류를 관찰한다. 클릭이나 저장만을 정답으로 취급하지 않고, 연구실 노출 위치와 더미 후기의 영향을 분리한다. 사용자 데이터·질의 수집은 동의와 보존 정책을 먼저 정한다.

## 실행 순서와 중단 기준

1. **평가 인프라:** 질의·판정 스키마, 해시 매니페스트, 익명화, 판정 UI/CSV, 재현 스크립트.
2. **A/B/C 비교:** 새 정제본의 동일 문단·동일 질의·동일 모델 버전으로 실행. 품질 이득이 없으면 sparse를 제품에 넣지 않는다.
3. **근거 검사:** 상위 후보의 주장·출처 span을 검사하되 순위 점수 가산은 별도 실험에서만 채택한다.
4. **D 및 시스템 최적화:** C가 통과하고 운영 지연 여유가 있을 때만 재순위화를 시험한다. Kaggle 쿼터·콜드 스타트가 병목이면 대기 경험/캐시/워커 공급을 별도 개선 과제로 다룬다.
5. **제한 공개:** 오류 신고와 사용자 효용 측정 후 확대한다.

이 계획은 검색 정확도, 근거 충실도, 과목 준비도, 운영 성능을 서로 다른 판정 대상으로 유지한다. 어느 단계에서도 과거 오염 벡터나 이전 4개 학과 정답을 새 데이터의 성능 증거로 재사용하지 않는다.
