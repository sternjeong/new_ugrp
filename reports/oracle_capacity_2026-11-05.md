# Oracle Micro 서비스 용량 관찰 (2026-11-04~05)

대상: `3mincurri.duckdns.org`, Oracle E2.1.Micro(메모리 1GB), Kaggle T4 BGE-M3 워커. 운영 환경에서 소규모 요청만 보냈다. 숫자는 최대 수용 인원이나 장시간 부하 보증이 아니다.

공개 주소의 순차 측정은 `POST /api/search`와 이어지는 `GET /api/session`까지 잰 것이다. 실제 브라우저 DOM 렌더링 시간은 별도 측정하지 않았다. 내부 동시 검색은 `127.0.0.1:8200`에서 요청별 다른 테스트 IP를 사용해 1분당 IP별 20회 제한의 영향을 피했다. Kaggle 워커는 요청을 한 번에 하나씩 처리하고 서버는 각 요청을 6초 기다리므로, 동시 10건에서는 사전 검색으로 전환된 요청이 있었다. GPU 대기열, 질의 길이, 사용자 행동, 네트워크에 따라 달라진다.

초기 측정에서는 빈 교수명 정렬 오류로 동시 검색 500이 발생했다. `CuratedCatalog`에서 빈 이름을 연구실 이름으로 대체한 뒤 위의 내부 동시 검색을 다시 측정했다. 원시 기록은 [수정 후 JSON](oracle_load_probe_2026-11-04.json)과 [초기 실패 JSON](oracle_load_probe_initial_2026-11-04.json)에 있다.

화면은 워커 자동 시작을 최대 3분 기다리도록 조정했다. Kaggle 시작이 그보다 늦거나 실패하면 사전 검색 결과를 보여 준다. 운영 계획에서는 **동시 5개의 서로 다른 임베딩 검색까지 이번 측정에서 성공**, 동시 10개에서는 임베딩 품질 저하가 있었다고 해석한다. 사이트 접속자 수의 상한은 이번 소규모 시험만으로 결정할 수 없다.
