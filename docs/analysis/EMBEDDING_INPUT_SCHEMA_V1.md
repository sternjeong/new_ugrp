# 목적별 임베딩 입력 뷰 계약 초안

작성일 2026-10-16. `FINAL_DATASET_SCHEMA_V2_DECISION.md`의 원본·근거·주장 계약에 붙는 **파생 검색 입력 계약**이다. `final_courses.jsonl`과 `final_labs.jsonl`은 원자료로 보존한다. 현행 `curri/` 앱에 적용된 스키마가 아니다. 두 Luna가 사전등록한 18개 구성요소의 제한적 결과를 독립 검산해 수용했다. 아래 기본 입력 선택은 그 범위 안에서의 결정이다.

## 목적과 레코드

| `purpose` | 후보 검색에 쓰는 텍스트 | 검증해야 할 별도 관계 |
|---|---|---|
| `lab_discovery` | 연구실의 직접 연구 주제·문제·재료와 출처가 분명한 논문 연구 내용 | 학생의 관심 ↔ 연구실의 `studies` |
| `course_preparation` | 연구실의 방법·도구 및 과목의 설명·진도에 나타난 실제 교육 내용 | 연구측 `uses/develops` ↔ 과목측 `teaches`의 동일 뜻 |
| `course_search` | 과목명·설명·진도 및 검토된 학습 맥락 | 사용자의 학습 목표 ↔ 과목에서 가르치는 내용 |

`embedding_view` 필수 열은 `view_id`, `entity_kind`, `entity_id`, `purpose`, `profile_version`, `chunk_id`, `source_evidence_ids`, `field_paths`, `text_sha256`, `token_limit`, `inclusion_reason`, `exclusion_policy`, `created_at`이다. `source_evidence_ids`는 현재 staging에 근거 레코드가 없으면 null이 아니라 빈 배열과 `evidence_status=not_built`를 함께 기록한다. 근거 ID가 존재한다고 주장할 때에는 `source_evidence` 외래 키와 정확한 원문 span을 검증한다. `chunk_id`는 `(profile_version, entity_kind, entity_id, purpose, field_paths, 정규화 텍스트 SHA)`에서 안정적으로 생성한다. 프로필 버전은 필드 포함 규칙과 정규화 규칙이 바뀌면 올린다.

벡터 저장 계약은 `embedding_vector(chunk_id, model_id, model_revision, tokenizer_version, max_tokens, normalized, vector_ref, computed_at)`이다. 벡터를 원문 엔터티와 동일 레코드에 덮어쓰지 않는다. 모델·청크 규칙이 바뀌면 검색 인덱스를 다시 만든다. GPU 모델 인코딩과 벡터 행렬 연산은 사용자 지시에 따라 Kaggle GPU에서만 실행한다.

## 이번 평가에서 고정한 직렬화

연구실 기본 `core`는 `keywords` 순서 결합 청크 한 개와 첫 다섯 대표 논문의 제목·정규화한 초록 앞 400문자 청크다. 과목 `core`는 `course_title + description[:1000]`, `course_title + Lecture progress plan[:1000]` 두 청크다. 빈 값은 청크를 만들지 않는다. 이메일·전화 정규식을 제거하고 공백을 정리한 뒤 최대 256모델 토큰에서 절단한다. 원문 배열 순서를 보존한다. 실험 당시 적격 보류는 연구실 핵심 929, 과목 핵심 1,882청크였다. 과목 핵심 285개는 256토큰에서 잘렸다. 앞 다섯 논문과 256토큰은 최적값으로 검증된 것이 아니라 **비교를 위해 고정한 설정**이다.

운영 필드 실험군은 연구실의 교수 직위·소속, 학과, 센터, 연구실 사이트 유무와 과목의 학점·범주·학과·학기·평가 문구를 `core`에 더한다. 선수사항·교재·참고자료는 별도 `learning_context` 실험군이다. 연구실 운영 청크 180, 과목 운영 청크 941, 학습 맥락 청크 920개였다. 학과·센터는 주제 신호가 될 수 있으므로 평가 결과 전에는 무조건 잡음으로 분류하지 않는다.

## 기본 제외와 보존

학생·교수 이름, 대학원생 수, 연락처, 오피스·위치, `admission`, `lab_mates`, `course_operation`, `other_info`, URL 원문, 전체 JSON 객체는 이번 `course_preparation` 임베딩 입력에서 제외한다. 원본 삭제를 뜻하지 않는다. 화면 표시, 출처 추적, 필터에는 용도와 권한에 따라 별도 저장한다. 특히 오피스 위치·학생 수는 이번 GPU 비교에 실제로 포함하지 않았으므로 제외의 효과 크기는 미측정이다. `research_intro`에는 연구 문장과 사람·뉴스·연락 문장이 섞여 있어 문단별 주장·행위 주체·출처 검사가 완료될 때까지 전체를 통째로 넣지 않는다.

## 규칙 엔진과의 접점

임베딩 점수는 넓은 후보를 찾는 점수다. 출처가 확인된 `assertion`과 검토된 `concept_sense`가 있어야 준비 과목의 직접 근거가 된다. 논문 목록의 `paper_listing` 주장은 연구실 자신의 현재 사용 주장으로 자동 승격하지 않는다. 제목만 맞거나 다의어의 뜻이 해결되지 않으면 `insufficient_evidence`를 반환한다. 추천 기록은 `retrieval_score`, `rule_adjustment`, `dedup_adjustment`, 버전과 판정 상태를 분리한다. 이전 B1 고정 +0.08 가산은 두 Luna의 이득이 입증되지 않아 제품 기본값으로 확정하지 않는다.

## 배포 전 확인

필드 제거 실험의 새 18구성요소·28교수 행에서 두 Luna가 327쌍을 독립 판정했다. 근거부족은 0쌍이었다. 사전 정의한 `core−both_admin`의 구성요소 가중 고정 5칸 효용 차이는 A +0.212(95% 구간 +0.117~+0.308), B +0.222(+0.113~+0.333)이다. 두 구간 하한이 사전 문턱 +0.02를 넘었다. 따라서 `course_preparation`의 **기본 후보 검색 입력은 위 `core` 청크**로 고정하고 연구실·과목 운영 청크를 기본 dense max-cosine 후보 점수에 더하지 않는다. `lab_discovery`와 `course_search`에는 이 우열을 이전하지 않는다. 운영 메타데이터는 엔터티 식별·필터·화면 표시에서 필요에 따라 별도로 사용한다.

이 선택이 가리키는 품질은 `core` 근거 창에서 평가 가능한 준비 과목 적합도에 한정된다. 18개 구성요소는 전체 137개 보류 구성요소의 새 무작위 표본이 아니며, 메타데이터 자체가 담는 유효한 연구 신호는 같은 평가 창에서 가려졌다. 두 Luna가 동일 과목 본문 코드에 불일치 점수를 준 그룹이 A 6개·B 2개 있었지만, 원 점수를 보존한 사후 최저/최고 일관화 민감도에서도 확인 문턱은 유지됐다. 이는 새 판정이 아니며 주요 결과를 대체하지 않는다. 연구실 발견 질의, 실제 학생 도움, 분야별 성능, 새 인코더, 다른 토큰 상한은 별도 검증이 필요하다.

사용자가 예로 든 오피스 위치와 대학원생 수는 개별 효과를 주장할 표본이 없다. 사후 정규식 감사에서 새 확인 표본 28행의 오피스 위치 가능 표지는 1행, 숫자 인원 가능 표지는 2행, 값이 있는 `lab_mates`는 0행이다. 이는 실제 위치·인원 값의 정확한 판정도 아니므로 직접적인 임베딩 성능 실험의 n으로 대체하지 않는다. `specific_noise_support_audit.json`의 전체 보류 180행에서도 각각 16·9·6행이었다. 연구 주제와 무관한 개인·위치 정보를 기본 임베딩 뷰에서 제외하는 것은 데이터 최소화와 목적 적합성에 따른 설계 선택이며, 이 필드들의 개별 성능 하락률이 검증됐다는 주장은 아니다.
