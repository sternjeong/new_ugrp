# 최종 데이터셋 스키마와 연결 그래프: 작업 기록

작성일: 2026-10-14. 대상은 저장소 루트의 `final_courses.jsonl`과 `final_labs.jsonl`이다. 이 문서는 구현·평가 전 설계 초안이다.

## 확인한 범위

- 과목 1,316행, 연구실 365행. 두 파일 모두 모든 행이 JSON 객체로 파싱되며 각각 16개, 20개 최상위 필드를 공통으로 가진다.
- 기존 앱의 419과목·65교수 및 기존 실험의 56~58 연구실과 모집단이 다르다. 기존 성능 수치를 최종 데이터셋 결과로 옮길 수 없다.
- 과목 코드 1,316개는 현재 파일에서 모두 고유하고 복합 코드 표기도 없다. `_semester`는 `2025 090`, `2025 092`, `2026 090`, `2026 092` 네 값이며 `professor`는 개설 정보다. 향후 다른 학기를 합칠 때에만 동일 코드의 반복과 내용 변화를 판정한다.
- **코드 고유성은 과목 내용의 고유성과 다르다.** 제목·설명·목표·진도를 공백 정규화하여 비교하면 125개 동일 내용 그룹에 335행이 속한다. 교차 개설(예: `CITE241`·`EECE480`·`MECH361`)과 공통 논문연구/세미나 문구가 섞여 있다. `audit_course_identity.py`의 그룹은 검토 후보이며 자동 동등 과목 판정이 아니다.
- 연구실의 `advisor_id`는 현재 행의 교수 식별자이고 `lab_group`은 공유 사이트 묶음 후보이다. 둘을 같은 연구실 ID로 혼용하지 않는다.
- `site_papers`, `professor_papers`, `representative_papers`는 출처·선정 방식이 달라 각각 독립적인 근거 상태를 보존해야 한다. `abstract: null`은 제목 근거에만 쓸 수 있다.

## 권장 정규 스키마

원본 두 파일은 불변 입력으로 보관하고, 다음 엔터티와 관계 테이블을 별도 생성한다. 모든 생성 레코드에는 `schema_version`, `source_file`, `source_sha256`, `source_row`(1부터 시작), `source_field`, `extractor_version`, `review_status`를 둔다. 사람이 보충한 내용은 `assertion_origin: human`으로, 자동 추론은 `assertion_origin: inferred`로 구별한다. `null`은 미확인이고 빈 문자열은 정제 때 null로 바꾸며 명시적인 '없음'과 합치지 않는다.

| 엔터티 | 필수 키와 주요 필드 | 단위 |
|---|---|---|
| `course` | `course_id`, `canonical_code`, `title`, `code_aliases`, `crosslist_group_id`, `content_group_candidate`, `identity_status` | 코드별 과목 단위; 실제 교차 개설 여부는 검토 후 기록 |
| `course_offering` | `offering_id`, `course_id`, `semester`, `professor_name`, `department`, `credits`, `source_row` | 학기별 개설 단위 |
| `course_evidence` | `evidence_id`, `offering_id`, `field`, `text`, `source_span`, `quality_flags` | 설명·목표·진도 중 문단/항목 |
| `advisor` | `advisor_id`, `name`, `department`, `researcher_id`, `identity_status` | 교수 개인 |
| `lab` | `lab_id`, `name`, `canonical_url`, `grouping_basis`, `grouping_status` | 후보로 노출할 연구실 |
| `lab_membership` | `lab_id`, `advisor_id`, `role`, `source_ref`, `review_status` | 교수와 연구실 연결 |
| `paper` | `paper_id`, `title`, `year`, `doi`, `abstract`, `venue`, `identity_status` | 중복 제거한 논문 |
| `paper_lab_evidence` | `paper_id`, `lab_id`, `advisor_id`, `source_list`, `source_ref`, `verification_status` | 논문의 연구실 소속 주장 |
| `concept` | `concept_id`, `preferred_label`, `aliases`, `broader_id`, `type` | 통제 어휘. `type`은 domain/problem/method/tool/material/knowledge 중 하나 |
| `assertion` | `subject_id`, `predicate`, `object_id`, `qualifiers`, `evidence_ids`, `assertion_origin`, `confidence`, `review_status` | 출처 있는 그래프 변 |

현재 파일에서는 정규화한 단일 `course_code`를 `course_id`로 쓸 수 있다. 다만 향후 다른 학기 자료를 합칠 때 코드 재사용·내용 변화를 다시 검사한다. `offering_id`는 원본 행에 영속 ID가 없으므로 현재는 파일 해시와 행 번호로 재현 가능하게 만들고, 공급처 고유 ID가 생기면 매핑을 보존한다. `lab_id`도 `lab_group`만으로 확정하지 않고 URL 정규화·공동 사이트 여부를 검토한다. DOI가 없는 논문은 제목 정규화+연도 등으로 **중복 후보**를 만들고 원문 제목을 유지한다.

동일 내용 그룹을 곧 교차 개설로 자동 병합하면 논문연구/세미나처럼 여러 코드가 공통 소개문을 쓰는 경우를 잘못 합칠 수 있다. 반대로 그룹을 전혀 고려하지 않으면 실제 교차 개설이 추천 목록을 여러 칸 차지한다. `content_group_candidate`를 근거로 사람 검토 큐를 만들고 `crosslist_group_id`는 확인된 경우에만 채운다. 평가에서는 코드 단위와 검토된 학습 단위의 순위 중복을 따로 보고해야 한다.

### 현재 파일의 결측과 식별 위험

과목의 설명·학습목표는 각각 35/1,316행, 진도계획은 207행이 빈 문자열이다. 선수사항 301행의 공란은 '선수과목 없음'을 뜻하지 않는다. 교수명도 161행이 비었다. 연구실에서는 교수 객체가 52/365행, 소개가 98행, `lab_group`이 50행 비었다. `lab_group`의 비결측 315행 중 고유 값은 312개이고 세 값은 두 행씩 나온다. 동일 사이트가 실제 공동 연구실인지 사람이 검토해야 한다. 44행은 `lab_url`이 없고 `representative_papers`는 87행에서 비었다. 이 결측 상태는 추천 점수 0점이 아니라 `insufficient_evidence`로 노출해야 한다.

입력 SHA-256은 과목 `828aa18576fd6282d7ebc42acdc840c62e3260af908493bb424b70b66c092d65`, 연구실 `d8aaec626071062d6d9f03effe21b5258bd3b951515aed005908a9929eba4eb2`이다. 파일이 달라지면 여기서 시작한 집계·실험 판정은 다시 해야 한다.

논문 원자료의 근거 수준은 크게 다르다. `site_papers` 2,041건 중 초록 123건, `professor_papers` 32,927건 중 초록 53건, `representative_papers` 2,449건 중 초록 2,095건이다. 앞의 두 목록은 제목 위주이고, 대표 논문은 별도의 선정·저자 매칭 과정을 거친다. 세 목록의 행을 그대로 합산해 연구실 점수를 높이지 않는다. 대표 논문의 인용 수·선정 점수는 연구 주제 적합성 점수가 아니다.

## 규칙 기반 연결안

1. 소개 문단·논문 제목/초록에서 `lab/paper --studies--> problem/domain`, `--uses--> method/tool`을 추출한다. 메뉴·뉴스·구성원·모집 문구는 연구 내용 근거에서 제외한다. 제목만 있는 논문은 `title_only` 근거를 기록한다.
2. 강의 설명·목표·진도에서 `course_offering --teaches--> concept`을 추출하고 `coverage`(언급/소개/학습목표/반복 실습)와 `depth`를 구분한다. 참고자료·선수사항에만 등장한 개념은 `teaches`로 승격하지 않는다. 여러 학기에 반복 확인되면 과목 수준의 `teaches`로 집계하되 상충하면 학기별로 남긴다.
3. `lab --uses--> method`와 `course --teaches--> method`의 직접 교집합은 `supports_method` 후보로 둔다. 문제/도메인 교집합만으로는 준비 과목을 확정하지 않는다. `method --requires_knowledge--> concept`은 사람 검토 또는 명시적 근거가 있을 때만 거쳐서 `supports_foundation`을 만든다. 이 경로는 서비스 추론임을 표시한다.
4. `problem`과 `method`가 연구실의 **같은** 문단·논문에 함께 연결될 때 조합 관계를 인정한다. 서로 다른 문서에 각각 나온 단어를 조합해 새 연구 방향을 만들어내지 않는다. 과목과 연구실의 동일 교수·학과·코드 접두부는 후보 생성 단서까지만 쓰고 추천 근거가 되지 않는다.
5. 점수는 근거의 직접성, `teaches`의 깊이, 주제 특이성, 독립 출처 수(상한 적용), 최신성 확인 여부로 구성한다. 논문 수나 과목 개설 횟수가 많다는 이유로 점수를 누적하지 않는다. 상위 N개를 반드시 채우지 않고 설명 가능한 변이 없으면 보류한다. 연결마다 원문 조각과 경로를 반환한다.

## 실험 재현 계약

기존 `bge_m3`, `query_understanding`, `reason_engine`, `ab_test`, `feedback_gate`는 서로 다른 과제·표본·평가자·지표를 가진다. 기존 README의 결과는 구 데이터에서 얻은 참고 가설이다. 최종 파일에 대해 입력 변환 버전과 해시, 샘플링 시드, 블라인드 키, 규칙·임베딩·LLM 설정, 평가 라벨을 고정하고 새 실험으로 재실행해야 한다. 특히 기존 `query_understanding`의 정답은 앱 개념에서 생성되어 규칙 검색에 유리하고, `feedback_gate`의 가짜 사용자와 평가가 같은 Claude 라벨에 의존한다.

재현 순서는 (1) 스키마/그래프 검증 및 사람 검토 샘플, (2) 최종 데이터에 맞춰 독립 작성한 질의와 연구실·과목 쌍 정답을 사전 고정, (3) 기존 기준선과 새 그래프 규칙, 임베딩/LLM 혼합 모델을 같은 후보 집합에서 블라인드 비교, (4) 이유 문장의 사실성 및 근거 추적 평가, (5) 피드백 시뮬레이션이다. 평가에는 부정 질의 혼입, lab recall/P@5, 과목 0점 비율·핵심 회수율, 근거 충실도, 그래프 변의 사실성, 미응답/결측 구간을 포함한다. 두 Luna 심사위원에게는 방법 이름을 숨긴 동일 패킷을 독립 제공하고 판정 차이를 기록한다. 심사 결과가 기각이면 해당 실패 유형을 수정해 새 홀드아웃에서 다시 평가한다. 최종 데이터에 대한 개별 실험 실행과 결과 심사는 아직 수행하지 않았다.

## 2026-10-14 설계 심사와 판정

독립 Luna 심사위원 두 명이 이 문서와 최종 파일·기존 실험 README를 검토했다. 두 심사 모두 **설계 초안은 조건부 수용, 성능 검증은 미완료**로 판정했다. 두 명 모두 과목 코드 중복을 현재 파일의 사실처럼 적은 오류를 발견했고, 위 내용을 현재 파일에서 중복 0건으로 정정했다. 심사 A는 모든 생성 레코드에 파일 해시와 1부터 시작하는 행 번호를 요구했으며 스키마에 반영했다. 심사 B는 `lab_group` 병합, 논문 목록 규모 편향, 새 후보 집합의 독립 홀드아웃 필요성을 강조했다. 이 설계 심사는 각 실험의 결과 심사를 대신하지 않는다.

기계 감사는 `python3 experiments/final_graph/audit_inputs.py`로 재현한다. 이 도구는 두 파일의 해시, 키·결측·타입, 코드/연구실 묶음 식별자, 논문 출처군별 초록·DOI 보유량을 출력한다. 본 문서의 집계는 2026-10-14 실행 출력과 일치한다.

## 정규화 구현 상태

`python3 experiments/final_graph/normalize.py --out /tmp/ugrp-final-graph-staging`으로 출처 보존 중간 자료를 만들었다. `python3 experiments/final_graph/validate_staging.py --out /tmp/ugrp-final-graph-staging`에서 모든 참조 ID와 8,957개 근거의 원문 위치를 확인했다. 생성 수는 과목 1,316, 개설 1,316, 임시 연구실 365, 교수 365, 교수-연구실 연결 365, 논문 식별 레코드 37,323, 논문-연구실 출처 주장 37,417, 텍스트 근거 8,957이다.

현재 `lab_id`는 `advisor_id`마다 하나의 임시 ID다. 이는 365개가 독립 연구실이라는 주장이 아니다. DOI 또는 OpenAlex ID가 있을 때만 논문 식별 레코드를 병합한다. 제목만 비슷한 논문 34,968건은 각각 출처별 미해결 레코드로 남긴다. `paper_lab_evidence`는 논문이 실제 그 연구실의 연구 방향을 대표한다는 검증된 변이 아니라 원본 목록에 수록됐다는 주장이다. 초록이 없는 항목은 `title_only`로 표시한다.

정규화 단계의 독립 Luna 심사 두 명은 **출처 보존 중간 자료로는 수용**했다. 심사 A가 지적한 논문 목록 참조 검증 누락을 보완하여 37,417개 논문-연구실 출처 주장과 37,323개 논문 식별 레코드를 원본 목록 항목과 다시 대조했다. 심사 B가 지적한 `source_field`의 과장 문제는 여러 필드에서 구성한 엔터티를 `$row` 출처로 명시하고, 모든 생성 레코드의 파일 해시·행 번호·스키마 버전을 검증하도록 고쳤다. 수정 후 전체 검증이 통과했다. 이 수용 판정은 의미적 연결 규칙의 정확성을 뜻하지 않는다.

정규화 파일에는 아직 개념 노드나 `studies`/`uses`/`teaches` 변이 없다. `evidence_role`도 필드의 용도를 표시할 뿐 사실성 판정이 아니다. 다음 단계는 추출 어휘를 새 모집단에 맞게 확장하고, 문단별 관계 유형과 부정·일반 언급·학습 수준을 구분한 뒤 사람 검토용 샘플에서 연결 오류율을 재는 것이다.

## 기존 개념 어휘의 문자열 후보 감사

`python3 experiments/final_graph/audit_vocabulary.py`를 실행하여 기존 `data/concepts.json`의 70개 개념 `keywords`만 최종 파일의 내용 필드에 맞췄다. 결과는 `experiments/final_graph/results/vocab_audit.json`에 해시와 함께 보관한다. `query_keywords`는 넓은 사용자 표현용이어서 제외했다. 연구실의 `keywords`·소개·대표 논문 제목/초록을 합친 주요 필드에서는 312/365행에 문자열 후보가 있었다. 사이트·교수 논문 제목/초록까지 포함하면 326/365행이다. 과목 제목·설명·목표·진도에서는 923/1,316행이다. 논문 출처군별 명중 행수는 사이트 제목 185, 사이트 초록 23, 교수 논문 제목 271, 교수 논문 초록 14, 대표 제목 244, 대표 초록 262다. 각 필드는 중복되므로 합산하면 안 된다.

## 개발 규칙의 후속 오류 수정

두 Luna 심사위원은 Q-learning을 일반 강화학습에서 분리하고 PINN의 복수형·약칭을 보완한 개발 수정이 원문에 맞는다고 판정했다. 한 심사위원은 소개문 안의 논문 제목을 연구실 소개 자체의 강한 `uses`로 잘못 취급하는 경로를 발견했다. 이를 반영해 첫 5개 대표논문 제목을 반복한 소개 조각을 제외하고, `simulation` 같은 명사를 사용 동사로 세지 않으며, 소개문에는 연구실 자신의 행위 문맥을, 논문 초록에는 해당 논문 자신의 행위 문맥을 요구한다. 전기촉매 공정(`electrocatalysis`)과 전기촉매 재료(`electrocatalyst_materials`)도 별도 유형으로 두었다.

현재 v15 개발 출력은 4,753개 후보 주장(과목 `teaches` 4,631, 연구실 `studies` 96·`develops` 12·`uses` 14)의 출처 위치 및 판정 패킷 노출 범위 검사를 통과했다. 연구실이 방법을 제안·개발한 근거는 `develops`로 분리하고, 과목 진도 한 텍스트 구간의 근거 강도는 여러 구간보다 낮춘다. 두 Luna 심사위원은 v14의 이 가중치를 개발 파일럿에 한해 수용했다. 한 심사위원이 구간을 실제 수업 회차인 `session`으로 부르면 과장이라고 지적하여 v15에서 `segment`로 이름을 바로잡았다. 순위 파일은 v14와 바이트 단위로 같다. 23개 개발 행 중 14개에는 직접 방법·도구 교집합 연결이 없다. 이는 엄격한 규칙의 누락 위험을 보여 주는 개발 진단이며 추천 성능 판정이 아니다. 보류 집합은 아직 실행하지 않았다.

과목 `prerequisites`에서 지식 어휘를 찾는 별도 감사는 최초 187개 후보를 두 심사위원이 기각했다. 필드 전체 부정문 때문에 유효 언급이 빠지고 `not required`를 필수 신호로 잘못 읽었다. 수정본은 `prerequisite_knowledge_mention` 과목×지식 개념 후보 198개만 기록하고, 정확한 별칭·주변 문맥의 원문 위치와 `required/recommended/ambiguous` **후보** 상태를 보존한다. 반복 어휘를 포함한 원문 출현은 223개이므로 198을 모든 언급 횟수로 해석하지 않는다. 이는 특정 과목의 선수지식 요구나 `method requires knowledge` 변을 확정한 결과가 아니다.

선수사항 필드의 과목 코드 언급도 별도로 추출했다. 적격 과목에서 현재 원본에 존재하는 코드의 334회 문자 출현을 찾았고 과목 코드 쌍으로 중복 제거하면 322개다. `prerequisite_course_code_mention`은 원문 문자열과 문맥만 보존한다. 부정·권장·병렬 선택 표현 및 교차 개설은 여전히 해석 전이므로 과목 간 필수 선수 관계로 자동 승격하지 않는다.

두 Luna가 `holdout_relevance_v1`의 910개 고유 쌍을 모두 블라인드 채점했다. 정확 일치율은 71.1%(647/910)이며 263쌍의 판정이 달라 심사위원별 지표를 합치지 않는다. 실패 사례를 결과 뒤에 점검했다. 두 심사위원이 모두 0점으로 판정한 `pair:000e492ab20d978a`는 논문 작성의 *logic*과 소자 논리 개념이 겹쳤고, `pair:013ddd2a0645d5cc`는 테라헤르츠파 *manipulation*과 로봇 조작이 겹쳤다. 이 사례는 모호한 별칭의 감지 필요성을 보여 주는 사후 진단이며 동결 v15를 같은 보류 자료에 맞춰 수정해 성능을 재주장하지 않는다.

사용자 지시에 따라 BGE-M3 CPU 인코딩은 순위 생성 전에 중단했다. Kaggle T4 GPU 실행 `20261014-234632-bge-rich-kaggle`에서 적격 941과목·표본 136행의 순위를 생성·해시 검증했다. 기본 BGE와 동결 규칙 0.08 가산의 상위 1개에서 기존 관계 판정 패킷에 없던 144쌍을 방법명 없이 두 Luna가 채점 중이다. 이 제한적 재실험은 옛 상위 3~5개·컷오프·재순위 결론을 재검증하지 않는다.

### 후속 심사 완료와 질의 실험

두 Luna는 위 관계·BGE 상위 1개·이유 문장 수치를 각각 **조건부 기술 결과**로 수용했다. B1 단독 추천 채택, BGE 규칙 보너스의 우월성, R1 문장의 일관된 유용성 향상은 어느 결과로도 입증되지 않았다. BGE 추가 판정의 정확 일치율 75.7%는 `relevance`만의 일치율이며, 예전 관계 라벨과 새 BGE 라벨을 같은 연구실·과목 쌍에서는 재사용했다. 새 라벨 사용 건수는 기본 BGE 125, 보너스 순위 110이며, 나머지는 기존 라벨이다. 근거 부족 표시가 있는 쌍의 부여 점수도 주 수치에 포함된다.

이유 문장 54개 중 46개의 과목 근거 span은 제목이었다. 따라서 이 파일럿은 과목이 실제 준비 기술을 가르치는지보다 주제·제목 연상의 충실도를 많이 검사한다. 동일한 두 Luna가 앞선 쌍을 판정했고 문장 형식도 드러나므로 독립 사용자 납득도 시험으로 해석하지 않는다.

질의 이해 제한 재실험은 `PREREG_QUERY_RICH.md`의 136개 적격 연구실 행·작성 질의 60개를 사용한다. v1과 v2 질의 파일은 순위 전 조사/파서 문제로 폐기하고 v3를 동결했다. 두 Luna가 v3 사전 설계를 수용했으며, 고정 파서의 목표 구절 진단에서는 명시적 부정 30개가 모두 보존되고 긍정 목표 11개는 의역으로 문자열이 부분 또는 불일치했다. CPU 희소 TF-IDF 순위와 방법 블라인드 433쌍 판정 패킷은 생성됐고 두 Luna의 판정은 진행 중이다. GPU 특화 BGE 추론은 앞서 Kaggle T4에서만 수행했다.

### 질의 이해 제한 결과와 블라인드 제한

두 Luna의 방법·순위 블라인드 433쌍 판정 및 결과 감사가 완료됐다. 명시적 부정 질의 30개에서 Q1−Q0의 상위 5개 관련 항목 비율은 심사 A +8.67%p, B +6.67%p였고, 5개 반환·위반 없음·관련 항목 1개 이상인 질의 비율은 A +23.33%p, B +26.67%p였다. 위반 질의 비율 차이는 A −6.67%p, B −13.33%p이지만 9개 순서 없는 주제 쌍 가족 bootstrap 구간은 둘 다 0을 포함한다. ### 합성 피드백 제거의 관문 스트레스 테스트

### A/B 표시 방식 제한 파일럿
