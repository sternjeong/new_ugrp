# 정리 거울(Intent Mirror) 명세

- 기준일: 2026-11-07
- 상태: **1단계(정리 표시)와 2단계(수정·확정) 구현**. 3단계 이후는 제안이며 승인 전에는 만들지 않는다.
- 구현: `curri/intent_mirror.py`(`build_mirror`, `clean_slots`), `POST /api/search` 응답의 `mirror`, `POST /api/mirror/confirm`, `Store.confirm_slots`, `curri/static/app.js`의 `mirrorHTML`·`mirrorAction`, `tests/test_intent_mirror.py`, `tests/test_http.py`

## 무엇이고 무엇이 아닌가

학생이 자신의 관심·방식·조건을 길게 적었을 때, **적은 말을 차원별로 나누어 원문 구절과 함께 돌려주는** 확인용 화면이다.

- 사람을 정의하거나 유형을 붙이지 않는다. ‘정체성’이라는 표현을 쓰지 않는다.
- 학생이 말하지 않은 차원은 채우지 않는다. 비어 있는 차원은 ‘아직 적지 않으셨어요’로 알린다.
- **검색 순위에는 쓰지 않는다.** 화면에도 그렇게 적는다. 학생이 확정하기 전에는 아무것도 저장하지 않는다.
- 제품 기획 3절의 ‘밝히지 않은 선호는 단정하지 않는다’와 ‘확정하지 않은 축을 수치로 채우지 않는다’를 따른다.

## 차원

| key | 표시 | 채우는 방법 |
|---|---|---|
| `topic` | 관심 주제 | 기존 질의 해석기의 `likes` 중 30자 이하만 사용. 문장 꼬리처럼 긴 결과는 주제로 쓰지 않는다 |
| `style` | 하고 싶은 방식 | 키워드 규칙(Python, 바이브코딩, 프레임워크, 설계, 실험 등) |
| `output` | 만들고 싶은 결과 | 키워드 규칙(데모, 논문, 창업, 특허, IP 등) |
| `constraint` | 환경·조건 | 키워드 규칙(인턴, N개월, 방학, 자율, 피드백, 부담 등) |

피하고 싶은 주제는 기존 해석기의 `dislikes`를 그대로 전달(`avoid`)한다. 새로 추정하지 않는다.

## 규칙

1. **원문 우선:** 슬롯 값(`values`)과 구절(`quote`)은 학생 텍스트의 부분 문자열이어야 한다. 구절은 값이 들어 있는 문장이며 100자 안에서 공백 경계로 자른다. (`topic` 값은 해석기가 정규화한 표현일 수 있고, 구절은 항상 원문이다.)
2. **노출 조건:** 텍스트가 40자 이상이고 **서로 다른 차원이 둘 이상** 잡힌 경우에만 만든다. 길이만으로는 만들지 않는다. 한 가지를 반복한 긴 글에는 보여 주지 않는다.
3. **영어 단어 안쪽 일치 금지:** `IP`, `Python` 같은 영어 키워드는 앞뒤가 영문자가 아닐 때만 인정한다(`shipping`, `API` 불일치).
4. **의도가 `search`일 때만:** 무의미·절차 질문·너무 넓은 입력에서는 만들지 않는다.
5. 키워드는 차원을 이름 붙일 뿐 연구실 점수에 쓰지 않는다.

## 수정·확정 (2단계)

- 학생은 값 칩을 지우고, 차원마다 직접 적어 추가하고(40자 이하, 차원당 8개까지), 비어 있는 차원도 채울 수 있다. 수정은 화면에만 있다가 ‘이대로 확정’을 눌러야 서버에 저장한다. 값을 모두 지우고 확정하면 저장된 정리가 삭제된다.
- 저장 위치는 현재 탐색 프로필의 `confirmed_slots`다(비회원은 세션, 회원은 계정). 서버가 `clean_slots`로 키(topic·style·output·constraint)·중복·길이·개수를 검증한다. 학생이 직접 쓴 값은 원문에 없어도 된다.
- **수명:** 같은 검색 문장으로 다시 검색하면 유지하고, 문장이 바뀌면 지운다. 확정한 정리가 다른 검색에 남지 않게 하기 위해서다. 그래서 새로고침·뒤로 가기에서는 유지된다.
- 확정한 뒤 화면에는 저장된 값만 보이고 ‘고치기’로 다시 편집한다. 피하고 싶은 주제(`avoid`)는 아직 편집하지 않는다.
- 확정한 정리는 어디에도 사용하지 않는다(검색·가이드·카드 모두). 활용은 3단계 제안이다.

## 화면

검색 결과 상단 ‘이렇게 이해했어요’ 아래에 접을 수 있는 영역(기본 열림)을 둔다. 차원마다 이름, 값 칩, 원문 구절을 보여 준다. 아래 안내를 항상 붙인다.

- 비어 있는 차원: “아직 적지 않으셨어요: … 적으면 더 잘 설명해 드릴 수 있어요.”
- “적어 주신 문장에서 표현을 그대로 가져온 정리일 뿐이에요. 어떤 사람인지 판단한 것이 아니고, 검색 순위에는 쓰이지 않았어요.”

## 알려진 한계

- 키워드 규칙이라 말을 돌려 쓰면 놓친다. 오탐도 있다. 예: ‘C++ 부담’의 ‘부담’이 환경·조건으로 분류된다.
- 한 구절이 여러 차원에 중복으로 보일 수 있다.
- 기존 해석기는 긴 글에서 관심 주제를 문장 꼬리까지 잘못 길게 자르는 경우가 있다. 거울은 이를 걸러 쓰지만 해석기 자체의 문제는 그대로다.
- 규칙의 정확도와 학생이 실제로 도움이 된다고 느끼는지는 아직 측정하지 않았다. 테스트는 ‘원문에서만 가져온다’, 노출 조건, 확정 검증과 저장 수명을 확인할 뿐이다.
- 2026-11-07 브라우저(Playwright) 확인: 표시, 칩 삭제, 직접 추가, 확정, 새로고침 뒤 유지가 동작했다. 이때 여러 문장을 한 덩어리로 읽어 관심 주제가 비던 문제를 찾았다. 그래서 `classify_curated_query`가 문장과 ‘…싶고,’ 절마다 따로 해석하게 했고, 방식·결과·조건 키워드가 든 구절은 주제에서 뺀다(`tests/test_intent_mirror.py`). 문장별 해석은 운영 검색 질의에도 그대로 쓰인다.

## 3단계 이후 제안 (미승인)

1. 확정한 슬롯을 연구실 카드의 ‘내 조건과 맞는 점 / 자료에 없어 직접 물어볼 것’으로 보여 준다. 순위 반영은 별도 결정이다.
2. 자료에 없는 항목(IP 정책, 지도 방식 등)을 쪽지·만남 약속에 쓸 질문 목록으로 만든다.
3. 거울 노출 vs 미노출을 기간별로 비교한다. 먼저 볼 지표는 ‘학생이 고쳤는가’이며, 원문에 없는 내용이 섞인 비율은 사람이 확인한다. 무작위 배정이 아니므로 인과 효과는 아니다.
