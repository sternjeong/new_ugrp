# 커피챗 요청·쪽지함 사용자 동선 시안

[클릭 가능한 HTML 시안](coffee_chat_user_pipeline_2026-11-02.html)은 가상 연구실·대학원생·대화로 동작한다. 실제 서비스에 연결된 화면은 아니다.

1. **처음 화면:** 자연어로 관심을 입력한다. 우측 `받은 쪽지함` 카드에서 최근 답장과 읽지 않은 수를 확인한다. 로그인하지 않았다면 쪽지 내용 대신 로그인 안내를 보여야 한다.
2. **연구실 추천:** 추천 이유를 보고 연구실을 선택한다. 대학원생 수는 별도 보조 정보로 표시하며 추천 순위에는 반영하지 않는다.
3. **연구실 상세:** 해당 연구실에 사전 등록하고 연락을 허용한 대학원생만 보여준다. 연구 분야·과정·도움을 줄 수 있는 주제를 확인하고 한 명을 고른다.
4. **커피챗 요청서:** 학생의 이름·학과·관심 분야를 프로필에서 가져와 수정할 수 있게 한다. 지금 관심 있는 연구 분야, 연락 목적(연구실 궁금 / 진로 상담 / 학부 연구참여), 선택형 질문을 받는다. 선배에게 전달되는 문장을 즉시 미리 보여주고, 학생이 확인한 뒤 전송한다.
5. **쪽지함:** 요청 직후 `답장 대기` 대화가 생긴다. 선배가 답하면 첫 화면 우측 카드와 쪽지함에 표시하고, 대화 안에서 시간·대면/온라인 방식을 조율한다. 요청 전송만으로 커피챗 일정이 확정되지는 않는다.

## 현재 구현과 연결점

현재 앱에는 연구실별 선배 카드(`seniorCard`), 쪽지 작성(`openContact`), 받은 쪽지함(`renderInbox`), 스레드별 답장(`threadHTML`)이 있다. `curri/static/index.html`의 상단 메뉴에는 로그인 시 쪽지함 버튼과 읽지 않은 수가 표시된다. 이 시안은 이를 **첫 화면 우측 요약 카드**와 **목적 기반 커피챗 요청서**로 확장한 제품 화면이다.

현재 `openContact`는 인사말만 채운 자유 입력 쪽지와 프로필 공유 미리보기를 사용한다. 실제 구현 시 요청서의 `연락 목적`, `현재 관심 연구 분야`, `선택 질문`을 구조화해 저장하거나, 발송 시 조합한 본문을 현재 `POST /api/contact`의 `body`에 넣을 수 있다. 목적별 필터·통계·후속 UI가 필요하면 구조화된 저장이 적합하다. 프로필의 학과는 현행 선택 항목이므로, 요청 전에는 입력을 요구하거나 `미입력`으로 명확히 표시해야 한다.

선배의 연락 동의와 등록 상태는 서버에서 계속 확인해야 한다. 학생에게는 전송할 프로필 내용을 확인하게 하고, 선배에게는 학생의 연락 목적·연구 관심·질문이 한눈에 보이도록 한다. 실명과 이메일 공유 범위는 현재 `openContact`의 정책과 함께 검토한다.
