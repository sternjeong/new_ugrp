## 2. 엔진에 돌려주는 네 가지 경로

### ① 피드백 재정렬 (온라인, 자동)
- **검색 키:** 해석기가 뽑은 관심 구절을 정렬해 만듭니다(`query_key`). 그래서 표현이 달라도 해석이 같으면 근거를 공유합니다.
- **점수:** 연구실마다 `열람 0.5 + 저장 2 + 연락 3 + 👍 2 − 👎 2.5`를 더하고, 평활화합니다(`s / (3 + |s|)`). 한두 번의 클릭으로는 순서가 크게 바뀌지 않습니다.
- **적용 조건:** 신호 합이 4점 이상 쌓인 검색에서만 바꿉니다.
  - 엔진 순서(RRF 점수)에 피드백 점수를 조금 더합니다.
  - 점수가 높은데 결과에 없던 연구실은 최대 2곳 끌어올립니다. 카드에 "같은 관심의 학생들이 도움이 됐다고 했어요"라고 표시됩니다.
- **실험:** `rank` 실험의 `feedback` 군(기본 50%)에만 적용합니다. 관리자 **엔진 개선**에서 두 군의 열람/검색 비율을 비교합니다.

### ② 평가셋 (오프라인 측정)
- 👍·저장·연락이 있는 검색이 자동으로 정답 세트가 됩니다(`judgments`, 이득 최대 3, 👎는 −2).
- 관리자 **엔진 개선 → 지금 평가하기**를 누르면 각 질의를 현재 엔진(캐시된 의미 검색 + 사전 검색)으로 다시 검색합니다. 그리고 nDCG@10, MRR, Recall@10을 냅니다.
- 점수가 낮은 질의 목록이 다음에 손볼 곳입니다.
- **평가셋 내보내기**로 받은 JSON은 `experiments/`의 오프라인 실험(재순위화, LLM 해석, 가중치 학습)에 그대로 씁니다.
- **주의:** 피드백 재정렬 nDCG는 같은 피드백으로 평가하므로 낙관적입니다. 진짜 효과는 A/B로 판단합니다.

### ③ 사전 확장 (운영자가 확인 후 반영)
- 결과 0건 검색어와 불만족(👎·검색 만족 2점 이하) 검색어를 엔진과 같은 규칙으로 단어로 나눕니다. 그중 사전에 없는 단어를 횟수 순으로 보여 줍니다.
- 운영자가 영어 연구 용어로 확장을 추가하면 `.local/expansions.json`에 저장되고, 즉시 사전 검색에 반영됩니다.

### ④ AI 가이드 재생성
- 👎 이유와 의견, 이전 주제 제목을 프롬프트에 붙여 다른 방향의 주제 2개를 다시 받습니다. 같은 인용·과목 검증을 거칩니다.
- 👎 이유 분포는 관리자 **피드백**에 집계됩니다. 프롬프트 개선(`research_guide.RULES`)의 근거로 씁니다.

## 3. 다음 단계 (데이터가 쌓이면)
1. **가중치 학습:** 평가셋이 100개를 넘으면 사전 검색, 의미 검색, 과목 연결, 피드백의 RRF 가중치를 nDCG 기준으로 학습합니다.
2. **재순위화 실험:** 상위 30곳 cross-encoder 재순위를 평가셋으로 비교합니다.
