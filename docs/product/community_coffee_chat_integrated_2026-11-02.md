# 연구실 후기·커피챗·일정 통합 시안

[통합 클릭형 시안](community_coffee_chat_integrated_2026-11-02.html)은 실제 서비스의 자연어 검색을 출발점으로 삼는다. 연구실·후기·대학원생·대화·점수는 모두 가상 예시다.

## 학생 흐름

1. 첫 화면에서 관심을 입력한다. 우측에는 로그인한 학생의 최근 쪽지와 읽지 않은 수가 보인다.
2. 추천 연구실을 선택한다.
3. 연구실 상세에서 **연구참여 후기 요약 3개 막대(지도·소통 / 연구 자율성 / 분위기), 개별 후기, 연락 가능한 대학원생**을 같은 화면에서 확인한다. 연구실 평가와 추천 순위는 별개다.
4. 대학원생을 고르면 프로필 정보가 채워진 커피챗 요청서가 열린다. 현재 관심 연구 분야·목적·선택 질문과 만남 방식(온라인 Zoom / 오프라인 교내 카페)을 고르고 전달 문장을 확인한다.
5. 요청 전송 뒤 쪽지함에서 시간을 제안한다. 대학원생이 수락해야 양측 합의 상태가 된다. 시안의 `선배가 제안 수락` 버튼은 상대방 행동을 재현하기 위한 것이다.
6. 합의 후 온라인은 Zoom 회의 생성, 오프라인은 교내 카페 좌석 예약을 시도한다. 연동 성공 후 양측 쪽지에 회의 링크 또는 카페 위치·예약 정보를 제공한다. Zoom 입장은 약속 시각에 활성화한다.

## 실제 구현에 필요한 상태와 연동

`requested → time_proposed → mutually_confirmed → provisioning → ready`를 구분한다. 예약 또는 회의 생성 실패 시 `provision_failed`를 별도 표시하고 재시도/방식 변경을 제공한다. 시간 변경·취소 시 기존 회의와 예약도 갱신하거나 취소해야 한다. 중복 클릭/재시도에 대비해 회의·예약 생성은 요청 단위로 멱등 처리하고, 외부 예약 확인 전에는 사용자에게 `예약 완료`라고 표시하지 않는다.

Zoom 회의 주소 생성은 서비스 서버가 Zoom 연동 권한을 가진 계정으로 회의를 예약 생성하는 방식이 필요하다. 생성된 주소는 해당 대화의 두 사람에게만 제공하고, 실제 만남 시각 전에는 입장 버튼을 비활성화한다. 회의 생성 시점은 양측의 시간 합의 후로 둔다.

교내 커피숍 자동 예약은 해당 매장의 예약 API, 제휴, 또는 별도의 예약 권한이 있어야 구현할 수 있다. 구체적인 매장과 예약 방식이 정해지기 전에는 `교내 카페 예약 요청`까지만 제품 계약으로 볼 수 있다. 연동에 성공한 경우에만 예약 번호·장소·시간을 확정 표시한다. 예약 채널이 없다면 같은 화면에서 학생이 직접 예약하도록 안내하는 후속 대안이 필요하다.

현재 앱의 `GET /api/community?lab_id=` 및 `POST /api/contact`, 쪽지함 API와 연결할 수 있지만, 구조화된 목적·만남 방식·일정 상태·외부 예약 식별자를 위한 서버 모델이 새로 필요하다. `연구 자율성` 역시 현행 후기 데이터에는 없으므로 실제 점수를 표시하기 전에 후기 입력·저장·집계 구조를 바꿔야 한다. 이전 후기에 없는 자율성 점수를 추정하지 않는다.
