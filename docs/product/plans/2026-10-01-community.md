# 3분커리 커뮤니티 확장 Implementation Plan (연구참여 후기 · 확장 프로필 · 대학원생 선배 연락)

> 기준일 2026-10-01. 기존 MVP([2026-09-16 계획](2026-09-16-mvp.md))의 흐름을 유지한 채, 탐색 이후 단계(경험 공유·사람 연결)를 프로토타입으로 검증한다.

**Goal:** (1) 연구참여를 마친 학부생이 연구실 후기를 남기고 읽는 공간, (2) 실명·별명·이메일·학교·관심 분야를 필수로 받는 확장 프로필, (3) 연구실 상세에서 정보 공개에 동의한 대학원생 선배를 보고 웹 안에서 쪽지를 주고받는 기능을 더미 데이터와 함께 동작시킨다.

**Architecture:** 기존 구조(Python 표준 라이브러리 HTTP 서버 + SQLite + 바닐라 JS, 외부 의존성 없음)를 유지한다. 인증·탐색 소유권은 `curri/store.py`, 새 기능(프로필 검증, 후기, 선배, 쪽지, 더미 시드)은 `curri/community.py`로 분리한다. 실제 연구실·과목 데이터(`labs.jsonl`, `lab_profiles.jsonl`, `concepts.json`)를 그대로 쓰고, 사람 관련 데이터만 `data/community_seed.json`의 더미로 채운다.

**Spec:** [제품 기준](../PRODUCT_PLAN.md) 11절(이 확장에서 추가).

## 확정한 결정 (2026-10-01, 사용자 결정)

| 항목 | 결정 |
|---|---|
| 후기 작성 자격 | 로그인 + 필수 프로필 완성 + "연구참여를 마쳤어요" 자기 신고. 후기에는 '자기 신고 참여'로 표기. 인증 배지는 후속 |
| 후기 형식 | 4개 항목 1~5점(지도·소통 / 배운 점 / 업무량 적절성 / 분위기) + 참여 시기·기간·했던 일 + 좋았던 점·아쉬운 점·추천 대상 서술 |
| 후기 공간 | 연구실 상세 하단(요약 + 목록 + 작성) 및 전체 후기 게시판(상단 메뉴 `연구참여 후기`) |
| 선배 연락 | 웹 내 쪽지함. 학부생이 보내고 선배가 답장, 양쪽 모두 쪽지함에서 대화 확인 |
| 선배 이메일 | 로그인 사용자에게만 표시(비회원은 이름·과정·연구 분야만) |
| 프로필 입력 시점 | 회원가입 시 필수 항목 입력. 선택 항목은 가입 시 펼쳐서 쓰거나 `내 프로필`에서 수정. 비회원 첫 탐색 흐름은 그대로 |
| 필수 항목 | 이름(실명), 별명(화면 표시명, 중복 불가), 이메일, 학교, 관심 분야(개념 태그 1개 이상 또는 자유 입력) |
| 선택 항목 | 학과·복수전공, 학년, 연구참여 목표·희망 시기, 한 줄 소개, 자기소개·하고 싶은 말 |
| 더미 데이터 표시 | 화면에는 구분 표시 없이 실제처럼 보인다. 단 파일·DB에 `dummy` 표시를 남겨 일괄 제거할 수 있게 하고, 이메일은 수신 불가 도메인 `@postech.example`을 쓴다 |

## Global Constraints

- 기존 흐름(관심 입력 → 목록 → 단일 상세 → 과목 → 가이드 → 저장)과 '첫 연구실 비회원, 두 번째부터 로그인' 정책을 바꾸지 않는다. 후기·선배 정보 열람은 연구실 상세 안에서 함께 보이며 별도 로그인 경계를 추가하지 않는다.
- 공개 범위: 후기에는 별명과 (입력했다면) 학과·학년만 보인다. 실명·이메일·자기소개는 학생이 먼저 쪽지를 보낸 선배에게만 보인다.
- 선배는 `role = graduate`이고 `contact_consent = true`인 계정만 노출한다. 실제 선배 등록(이벤트 동의 수집, 초대 코드 등)은 후속이며, 이번에는 시드 계정만 존재한다.
- 이메일을 실제로 발송하지 않는다. 모든 연락은 서버 DB 안의 쪽지다.
- 서버가 세션으로 작성자·수신자를 결정한다. 다른 사람의 쪽지 스레드는 404로 숨긴다. 남용 방지: 하루 쪽지 30건, 후기는 연구실당 1개(수정 가능).
- 인라인 스크립트·스타일 금지(CSP 유지). 평점은 텍스트 별(★)로 표현한다.

## 3. API

Files: `curri/server.py`, `tests/test_http.py`.

| 경로 | 역할 |
|---|---|
| `GET /api/concepts` | 관심 태그 후보(개념 id·이름·성격) |
| `POST /api/register` | `{email, password, account}` 필수 프로필과 함께 가입 |
| `POST /api/account` | 내 프로필 수정(로그인) |
| `GET /api/community?lab_id=` | 연구실 후기 요약·목록, 선배 목록(이메일은 로그인 시), 내 후기 |
| `GET /api/reviews` | 전체 후기 게시판 |
| `POST /api/review` · `POST /api/review/delete` | 후기 작성·수정 / 삭제 |
| `POST /api/contact` | `{graduate_id, subject, body}` 선배에게 쪽지 |
| `GET /api/inbox` · `GET /api/thread?id=` · `POST /api/reply` | 쪽지함, 대화 보기(읽음 처리), 답장 |

로그인 필요 401 `login_required`, 프로필 미완성 403 `profile_required`, 권한 없음은 404.

## 4. 화면

Files: `curri/static/index.html`, `curri/static/app.js`, `curri/static/styles.css`.

- [x] 가입 다이얼로그에 필수 항목과 접히는 선택 항목. 관심 분야는 개념 태그 칩(검색 가능) + 자유 입력.
- [x] 상단 메뉴: `연구참여 후기` · `나의 탐색` · `쪽지함(안 읽은 수)` · `별명/로그인`. 별명을 누르면 `내 프로필`(수정·로그아웃).
- [x] 연구실 상세 하단 `먼저 경험한 사람들`: 후기 요약(항목 평균)·목록·작성 버튼, 재학 중인 선배 카드·쪽지 보내기.
- [x] 후기 작성·쪽지 작성은 공용 시트 다이얼로그. 로그인/프로필 미완성 시 각각 로그인 창, 내 프로필로 안내.
- [x] 쪽지함: 대화 목록 + 대화 보기 + 답장. 선배 화면에서는 보낸 학생의 프로필 카드를 함께 보여준다.

## 후속 (이번 범위 밖)

- 연구참여 사실 확인(운영자 승인, 학과 확인서 등)과 인증 배지, 후기 신고·숨김 등 운영 도구.

- 쪽지 알림(이메일·푸시), 차단·신고, 응답률 표시.
- 학교 이메일 인증, 실명 확인. 프로필의 관심 태그를 추천 검색에 반영할지 여부.
