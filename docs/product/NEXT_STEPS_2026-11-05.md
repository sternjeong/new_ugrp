# 다음 단계 제안: 추가 서비스와 검색 엔진 고도화 (2026-11-05)

가이드 비교 시제품: A는 기존, B는 교수의 최근 논문 선택과 OpenAlex 직접 참고문헌 후보를 제공한다. `bash tools/set_guide_variant.sh A|B`로 전체 사용자에게 노출할 버전을 바꾼다. 날짜·버전별 탐색과 가이드 생성 요청 수만 집계한다(반복 요청 포함). 무작위 배정은 구현하지 않았으므로 전환 자체를 엄밀한 A/B 실험 결과로 해석하지 않는다. B의 참고문헌은 후보일 뿐 기반 논문으로 검증되지 않았다.

운영 집계 확인: `ssh oracle-micro 'python3 - "$HOME/app/.local/curri.sqlite"' < tools/guide_variant_counts.py`. 배포 직후 A 탐색 1건은 운영 확인 요청이다. 전환 시 기존 가이드는 보존하지만 다른 버전에서는 재생성이 필요하다.

근거: 같은 날 진행한 실사용 점검이다. 로컬에서 운영과 같은 코드·데이터로 10개 시나리오를 실행했고, 운영 의미 검색(Kaggle BGE-M3)에 비회원 질의 20개를 보냈다. 고친 문제와 남은 문제는 `docs/analysis/SERVICE_CODEBASE_ANALYSIS.md`의 2026-11-05 메모를 따른다. 아래 우선순위는 제안이며 사용자 결정이 아니다.

2026-11-05 후속 반영: 과목 연결에 상대 유사도 기준·학과 가산·담당 교수 우선 정렬과 다섯 과목 별칭을 추가했고, 일부 문장형 관심을 구절로 분리했다. Kaggle push 전 status를 호출한다. 이 기준은 진단 사례에 대한 경험적 조정이므로 독립 평가와 운영 의미 검색 검증은 여전히 필요하다.

## 2. 검색 엔진 고도화

### 점검에서 확인한 현상

- 짧은 한국어 질의가 영어로 적힌 연구실 자료를 잘 찾지 못했다. 데이터에는 autonomous driving 5곳, drone/UAV 10곳, organic synthesis 7곳이 있었지만 수정 전 사전 검색은 0건이었다. 의미 검색 1위도 `자율주행`은 화학공학, `드론`은 의공학이었다.
- 운영 순위는 사전 검색과 임베딩 순위를 같은 비중(RRF k=10)으로 합친다. 그래서 사전 검색의 잡음(예: `인지` 한 단어 일치로 생명과학과 1위)이 그대로 상위에 올라왔다. 이번에 사전 검색을 고쳐 이 경로를 줄였지만, 임베딩 쪽 계산은 바꾸지 않았다.
- 규칙 해석기는 문장 구조에 약하다. "로봇 팔을 강화학습으로 제어하고 싶어요"는 후속 규칙으로 두 구절로 분리하지만 다양한 문장에 일반화되지는 않는다.
- 수업 경험 질의(`선형대수 재밌었어요`, `일반물리 수업이 재밌었어요`)는 연구실 자료와 직접 이어지지 않는다. 같은 날 해석기가 이런 어미를 떼고, 과목명을 담당 교수 연구실과 과목-연구실 유사도로 잇도록 고쳤다(아래 7번 1차 반영).
- 정제 데이터 기준 평가셋이 없다. 지금 있는 것은 작성자가 만든 진단 질의 20개뿐이라 개선 여부를 숫자로 말할 수 없다.

### 할 일 (순서대로)

1. **평가셋과 로그부터 만든다.**
   - 학과별 실제 학생 질의 80~100개에 정답 연구실을 판정한다(그 학과 학부생·선배가 검수).
   - nDCG@10, Recall@10, 0건 비율을 기준선으로 잰다.
   - 동의를 받아 질의·상세 열기·저장을 익명 로그로 남겨 암묵적 피드백으로 쓴다.
   - 아래 단계는 모두 이 숫자로 채택 여부를 정한다.
2. **질의 확장·번역.**
   - 한국어 질의의 연구 용어를 영어로 확장하거나 번역해 원문과 함께 임베딩한다.
   - 이번에 넣은 `EXPANSIONS`(약 50개)를 새 데이터 기준 개념 사전으로 정리한다. 지금 `concepts.json`은 이전 4개 학과용이다.
3. **문서 쪽 정리와 재임베딩.**
   - 빌더가 OpenAlex 분류를 연구실 `research_area`로, 출처를 홈페이지로 기록하는 문제를 고친다.
   - 연구실별 한국어·영어 요약과 대표 논문 초록 단위로 근거 문장을 다시 나눠 BGE-M3로 재계산한다. 이때 `lab_course_bge_m3.json`의 해시도 함께 갱신한다.
4. **하이브리드 개선.**
   - 문자열 일치 대신 형태소 분석(예: Kiwi) 기반 BM25를 쓴다.
   - RRF 비중을 평가셋으로 조정하고, 사전 검색이 약할 때는 임베딩 순위를 우선한다.
5. **재순위화.** GPU 워커에서 상위 30곳을 cross-encoder(bge-reranker-v2-m3)로 다시 매긴다. 정밀도 개선 폭이 가장 클 것으로 예상하는 단계다.
6. **질의 해석을 작은 LLM으로.**
   - 좋아함·싫어함·의도·연구 용어를 구조화해 추출한다.
   - 규칙 해석기는 실패 시 대체 경로로 남긴다.
   - 질의가 외부 API로 나가므로 개인정보 안내가 필요하다.
7. **과목에서 연구실로 잇기.** 과목명 질의는 담당 교수와 상대 유사도 기준을 통과한 후보를 보여 주고 일부 약칭을 인식한다. 남은 일: 연구실별 상위 20과목만 저장돼 있어 후보가 없는 과목이 있다. 전체 과목×연구실 유사도를 다시 계산하고 필터와 별칭을 학생 평가로 검증한다.
8. **시작 지연 줄이기.**
   - Kaggle 워커는 꺼져 있으면 첫 검색이 1~3분 걸리고 주간 GPU 한도의 영향을 받는다.
   - 대안은 짧은 질의만 임베딩하는 상시 CPU 워커(`tools/embed_worker/deploy_cpu_worker.sh`, 양자화 모델 검토)와 질의 임베딩 캐시다.
9. **결과 다양성과 설명.** 같은 학과가 몰리지 않게 MMR을 적용하고, 일치한 근거 구절을 강조해 보여 준다.
