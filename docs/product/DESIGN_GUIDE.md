# 3분커리 디자인 가이드 (2026-11-17)

화면을 고칠 때 따르는 규칙이다. 규칙의 값은 `curri/static/styles.css` 맨 위 `:root`에 있고, 이 문서는 그 값을 왜 그렇게 정했는지 적는다.

## 1. 왜 다시 정했나

2026-11-16에 "AI가 만든 웹디자인의 특징"과 "사람이 만든 검증된 디자인의 특징"을 조사했다. 기존 화면은 보라색 그라데이션 같은 2024~2025년형 특징은 없었지만, 2026년에 AI 도구들이 기본으로 내놓는 모습과 거의 겹쳤다.

| 2026년형 AI 기본 디자인 | 기존 화면 |
|---|---|
| 크림색 배경 + 주황(테라코타)·세이지 초록 포인트 | `#faf8f3` 배경, `#d95530` 주황, `#49624e` 초록 |
| 제목 위 자간 넓은 영어 대문자 라벨 | 22개 |
| 제목에서 한 단어만 강조 | "연구가 되는 곳." 주황 + 손그림 밑줄 |
| 모든 버튼에 화살표 | 약 40개 |
| 순서가 아닌 곳의 01/02/03 번호 | 카드 번호, 입력 칸 "01 / YOUR INTEREST", 원형 번호 |
| 아이콘 달린 똑같은 카드 3칸 | 첫 화면 "YOUR NEXT STEPS" |
| 지어낸 사용자 표시 | 가짜 프로필 동그라미 |
| 이모지를 아이콘으로 사용 | 👍👎😀 |
| 어디에나 쓸 수 있는 구호 | "가능성" 10회, "탐색" 19회, "연결" 19회 |

여러 자료의 공통 결론은 **"특정 색이나 글꼴이 아니라, 아무도 결정하지 않은 기본값이 쌓인 것이 AI 티"**라는 점이다. 그래서 다른 유행 스타일로 갈아타지 않고, 적은 수의 규칙을 정해 모든 화면에 똑같이 적용한다.

### 조사의 한계

- 특징 하나로 AI가 만들었다고 단정할 수 없다. 가장 큰 실측 조사(웹사이트 1,590개)도 오판율을 5~10%로 본다.
- "AI처럼 보이면 사용자가 불신한다"는 직접 연구는 찾지 못했다. 디자인 인상이 신뢰에 영향을 준다는 오래된 연구(Fogg 2002, Lindgaard 2006)만 있다.
- AI 디자인 특징을 다룬 자료 대부분은 디자이너·업체의 의견이다. 실측은 Krebs의 조사, 경험적 연구는 NN/g의 AI 프로토타이핑 연구 정도다.

## 3. 지키는 것

| 지키는 것 | 확인 방법 | 근거 |
|---|---|---|
| 내용의 우선순위에서 시작한다 | 화면마다 가장 중요한 것 하나가 가장 먼저, 가장 크게 | NN/g |
| 비교하는 목록은 카드 격자가 아니라 세로 목록 | 검색 결과는 한 줄에 연구실 하나 | NN/g |
| 크기만이 아니라 굵기·색·여백으로 중요도를 나눈다 | 글자색 3단계, 굵기 3종 | Refactoring UI, KRDS |
| 색마다 맡은 일이 하나 | 레드는 행동, 오렌지는 "내 관심과 닿은 것", 골드는 인용한 자료와 AI 제안. 같은 색이 다른 뜻으로 쓰이지 않는다 | KRDS, Linear |
| 정해진 값만 쓴다 | 색·글자 크기·여백·모서리·그림자는 토큰만 쓴다. 예외는 레드 바탕 위 흰 글자(`#fff`)와 체크박스·버튼 높이 같은 조작 요소의 고정 크기 | 다수 |
| 문구는 구체적으로, 해요체 하나로 | 버튼은 결과를 말한다. 뺐을 때 뜻이 안 변하는 문장은 뺀다 | 토스 글쓰기 원칙, GOV.UK |
| 근거는 주장 바로 옆에 | 연구실마다 연결 근거 문장 1개를 접지 않고 보여 준다 | NN/g, 스탠퍼드 신뢰도 지침 |
| 한글에 맞춘 글자 설정 | 어절 단위 줄바꿈, 본문 16px, 줄 간격 1.6. 안내 문장은 구절 단위로 줄을 바꾼다(아래 "줄바꿈") | KRDS, W3C |
| 블록은 세 단계로 구분한다 | 큰 구역 = 굵은 선 + 레드 제목, 항목 = 테두리 상자, 항목 안 묶음 = 소제목(아래 "블록 구분") | 사용자 의견 |
| 색만으로 상태를 전달하지 않는다 | 선택·오류는 글자나 테두리도 함께 바뀐다 | KRDS, WCAG |
| 일부러 다르게 한 곳은 한두 군데 | 화면 맨 위 포스텍 레드 선, 목록 위 굵은 검은 선 | 단일 자료 |

### 블록 구분 (2026-11-17 3차)

1차에서는 "상자보다 선과 여백"으로 구분했다. 직접 써 본 사용자가 블록 경계가 약해 읽기 어렵다고 해서 구분을 강하게 했다. 조사 자료보다 실제 사용자의 읽기 경험을 우선했다. 상자 속 상자는 한 단계까지만 쓴다.

| 단계 | 대상 | 모습 |
|---|---|---|
| 큰 구역 | 과목 고르기, 연구 가이드, 후보 저장, 선배·후기, 익명 질문, 계정 설정 | 구역 사이 64px, 위에 굵은 검은 선(2px), 제목은 포스텍 레드 |
| 항목 | 연구실, 과목 목록, 가이드 주제, 저장 후보, 후기, 선배, 질문, 설정 | 테두리 상자(`--line-strong` 1px, 모서리 8px, 안쪽 여백 16~24px), 항목 사이 16px |
| 항목 안 묶음 | 연구 분야, 연결 근거, 버튼 줄 | 굵은 회색 소제목(`.group-title`), 묶음 사이 16px, 버튼 줄 위에 구분선 |

- 연구실 정보(상세 왼쪽)와 첫 화면의 진행 순서는 옅은 회색 바탕 상자다. 안내문·빈 상태도 옅은 회색 바탕이지만 테두리가 없다.
- 선택한 과목은 바탕색(`--accent-soft`)과 체크 표시를 함께 쓴다.
- 구역 제목의 레드는 링크와 헷갈리지 않게 크고 굵게, 밑줄 없이 쓴다. 링크는 작고 밑줄이 있다.

### 줄바꿈 (2026-11-17 3차)

문제: 문단 폭을 좁게 제한한 데다 어절 단위로만 줄이 바뀌어서, "…이어지는 / 과목까지"처럼 구절 중간에서 끊기거나 마지막 줄에 한 어절만 남았다.

- 안내 문장은 쉼표·마침표로 끝나는 구절을 `<span class="ph">`(`display: inline-block`)로 묶는다. 줄은 구절 사이에서만 바뀌고, 구절이 화면보다 길 때만 그 안에서 어절 단위로 바뀐다. `app.js`의 `phrase()`가 화면에 추가되는 안내 문장에 자동으로 적용한다(`PHRASED` 선택자 목록).
- 짧은 안내 문장에는 `text-wrap: balance`로 줄 길이를 고르게 해 마지막 줄에 한 어절만 남지 않게 한다.
- 제목 아래 설명의 폭 제한(34~40em)을 없애 넓은 화면에서는 한 줄에 들어가게 했다.
- 연구실 소개, 논문 초록, 과목 설명처럼 데이터에서 오는 글에는 적용하지 않는다.
- 확인(2026-11-17): 화면 폭 1440·1100·850·620·390px에서 첫 화면, 검색 결과, 상세, 저장 목록, 후기 게시판, 개인정보, 로그인 창을 열어 "마지막 줄에 한 어절만 남은 안내 문장"이 0건, 가로 넘침 0건.

## 4. 토큰

### 색

바탕은 흰색·회색이고 기본 포인트는 포스텍 레드다. 포스텍 학생을 위한 서비스라는 점을 색으로 드러낸다. 값은 학교가 공개한 UI 색상 규정을 따른다.

레드 하나만으로는 화면이 밋밋하다는 사용자 의견(2026-11-17)에 따라 오렌지와 골드를 보조색으로 쓴다. 색마다 맡은 일을 하나씩만 준다.

| 색 | 맡은 일 | 쓰는 곳 |
|---|---|---|
| 레드 | 행동 | 주요 버튼(검색, 가이드 보기, 보내기), 링크, 선택된 항목 |
| 오렌지 | 내 관심과 닿은 것 | 일치한 낱말 표시, "관심과 일치" 표지, 연구실을 여는 버튼(이 연구실 알아보기, 이어서 보기), 현재 진행 단계 밑줄, 결과 수, 별점 |
| 골드 | 인용한 자료와 AI 제안 | 근거 인용문·내가 적은 문장·답변의 왼쪽 선, AI 가이드 상자 바탕 |

오렌지와 골드는 흰 바탕 위 명암비가 약 2:1이라 글자색으로 쓰지 않는다. 바탕이나 선으로만 쓰고, 그 위 글자는 검정(명암비 9 이상)이다.

| 이름 | 값 | 쓰는 곳 | 출처 |
|---|---|---|---|
| `--accent` | `#a61955` | 주요 버튼, 링크, 선택 상태 | 포스텍 레드 (Pantone 215 C, RGB 166/25/85) |
| `--accent-strong` | `#86123f` | 버튼 hover, 연한 바탕 위 글자 | 레드를 어둡게 |
| `--accent-soft` | `#f9ecf1` | 선택된 항목 바탕 | 레드를 연하게 |
| `--orange` / `--orange-strong` | `#f6a700` / `#df9700` | 연구실을 여는 버튼 바탕(hover), 현재 단계 밑줄, 별점 | 포스텍 오렌지 (Pantone 130 C, RGB 246/167/0) |
| `--mark` | `#fde6b0` | 일치한 낱말·"관심과 일치"·결과 수 바탕 | 오렌지를 연하게 |
| `--gold` / `--gold-soft` | `#daba65` / `#faf4e1` | 인용문 왼쪽 선 / AI 가이드 상자 바탕 | 포스텍 골드 (Pantone 872 C, RGB 218/186/101) |

| `--bg` / `--surface` / `--surface-strong` | `#ffffff` / `#f6f6f5` / `#ececea` | 바탕 / 옅은 채움 / 태그 | |
| `--line` | `#cfcfcb` | 구분선 (3차에서 `#e1e1de`보다 진하게) | |

명암비(흰 바탕 기준, 2026-11-17 계산): 본문 16.7, 보조 글자 8.4, 가장 조용한 글자 5.6(옅은 회색 바탕 위 5.1), 포스텍 레드 글자와 레드 버튼의 흰 글자 7.3, 오류 글자 7.4. 모두 4.5 이상이다.

### 글자

- 글꼴: Pretendard(서버에 직접 넣음, `curri/static/fonts/`, OFL 라이선스). 400·600·700 세 굵기만 쓴다. 서브셋에 없는 드문 글자는 기기 한글 글꼴로 대체된다.
- 크기 6단계: 14 / 16 / 18 / 22 / 28 / 36px. 14px 아래로 내려가지 않는다. 좁은 화면에서는 28·36px가 24·28px로 줄어든다.
- 줄 간격: 본문 1.6, 제목 1.3. `word-break: keep-all`로 어절 단위로 줄을 바꾼다.

### 여백·모양

- 여백: 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px
- 모서리: 4px(태그·칩), 8px(버튼·입력 칸·상자), 원형(숫자 배지)
- 그림자: 2단계. 떠 있는 것(알림, 대화창)에만 쓴다. 목록과 상자에는 그림자가 없다.
- 구분: 상자 테두리보다 가는 선과 여백을 먼저 쓴다. 목록의 시작은 굵은 검은 선으로 표시한다.
- 움직임: 로딩 표시만 있다. `prefers-reduced-motion`이면 멈춘다. hover 효과는 마우스가 있는 기기에서만 적용한다.

## 5. 쓰지 않는 표지

- **포스텍 로고·심볼·엠블럼·마스코트**: 등록상표이고 사용 승인이 필요하다. 색만 쓴다. 학교 공식 서비스로 보이지 않게 바닥글에 "POSTECH 학생이 만든 시제품이며 학교 공식 서비스가 아니에요."를 둔다.
- **오뚜기 3분 카레를 닮은 요소**(노랑 + 빨강 포장 배치, 로고, 글씨체): 서비스 이름이 이미 "3분 카레"를 떠올리게 하므로, 공개 홍보에서 연상이 더 커지지 않게 한다. 색 하나는 저작권 대상이 아니지만, 널리 알려진 표지는 이름·색·모양 전체 인상으로 부정경쟁방지법의 보호를 받을 수 있다. 법률 자문을 받은 판단은 아니다.

### 로고

2026-11-17에 확정했다. 직접 그린 지그재그 3(포스텍 오렌지)과 검은고딕 "분커리"로 이루어진다. 세로형, 가로형(사이트 머리글), 심볼(탭 아이콘·프로필) 세 형태가 있다. 파일과 사용 규칙은 [docs/brand/README.md](../brand/README.md). 로고의 한글은 검은고딕이고 화면 본문은 Pretendard다. 로고에만 다른 글꼴을 쓰는 것은 의도한 것이다.

|---|---|---|
| 첫 화면 제목 | 내 관심이 연구가 되는 곳. | 관심 분야를 적으면 POSTECH 연구실을 찾아 드려요. |
| 첫 화면 설명 | 좋아하는 것에서 시작해 보세요. 나와 연결되는 연구실을 발견하고, 어떤 연구를 해볼 수 있을지 하나씩 알아가요. | 연구실 소개와 논문에서 내 관심과 겹치는 내용을 찾아 보여 주고, 그 연구실과 이어지는 과목까지 알려 드려요. |
| 입력 칸 라벨 | 요즘, 무엇이 궁금한가요? / 관심 분야 또는 고민 | 무엇이 궁금한가요? (관심 분야, 재미있었던 수업, 고민 모두 괜찮아요) |
| 목적 선택 | 어떤 탐색을 하고 있나요? | 지금 어떤 단계인가요? |
| 소개 3칸 | 관심에서 연구실로 / 배운 것에서 가능성으로 / 가능성에서 나의 선택으로 | 이렇게 진행돼요: 1. 연구실 고르기 2. 들은 과목 표시 3. 연구 가이드 |
| 진행 표시 | 01 연구실 — 02 수강 경험 — 03 나의 가이드 | 연구실 고르기 › 들은 과목 표시 › 연구 가이드 |
| 결과 제목 | 관심에서 이어지는, 새로운 가능성. | 내 관심과 겹치는 연구실 |
| 결과 설명 | 하나씩 살펴보세요. 잘 맞는 이유와 앞으로 준비할 것을 함께 알아갈 수 있어요. | 연구실마다 어떤 문장을 보고 연결했는지 함께 보여 줘요. 관심 주제는 연구의 대상일 수도, 방법일 수도 있어요. |
| 결과 의견 | 찾았어요 😀 / 조금 😐 / 아니요 😞 | 찾았어요 / 일부만 찾았어요 / 못 찾았어요 |
| 상세 제목 | 배운 것에서, 시작해 볼까요? | 이 연구실과 이어지는 과목 |
| 상세 설명 | …아직 듣지 않았어도 괜찮아요. 앞으로의 준비를 함께 살펴볼게요. | 들은 과목에 표시하면 가이드에 반영돼요. 아직 들은 과목이 없어도 가이드를 볼 수 있어요. |
| 수강 안내 | 수강 경험은 출발점이에요. 실제 숙련도나 지원 자격을 판단하지 않아요. | 수강 여부로 실력이나 지원 자격을 판단하지 않아요. |
| 가이드 제목 | 지금의 나에서, 다음 연구로. | 연구 가이드 |
| 저장 칸 | 내가 발견한 가능성을 남겨보세요. | 후보로 저장하기 |
| 새 논문 알림 | ☆ 새 논문 지켜보기 / ★ 지켜보는 중 | 새 논문 알림 받기 / 새 논문 알림 받는 중 |
| 선배·후기 | 먼저 경험한 사람들. | 선배와 연구참여 후기 |
| 질문 | 익명으로 물어보기. | 익명 질문 |
| 로그인 창 | 다음 가능성도 이어 만나보세요. | 로그인 / 계정 만들기 |
| 바닥글 | 관심에서 시작하는, 나다운 연구의 발견. / POSTECH · PROTOTYPE | POSTECH 학생이 만든 시제품이며 학교 공식 서비스가 아니에요. |
| 저장 목록 제목 | 내가 남긴 가능성들. / 하나씩 살펴보고, 나에게 맞는 후보 2~3곳을 남겨보세요. | 나의 탐색 / 저장한 연구실 후보와 메모예요. 다시 열어서 이어 볼 수 있어요. |
| 저장 목록이 비었을 때 | 연구실을 살펴보고 마음에 남는 가능성을 저장해 보세요. | 연구실 상세 화면 아래의 ‘후보와 메모 저장’을 누르면 여기에 모여요. |
| 저장 항목 버튼 | 탐색 이어보기 | 이어서 보기 |
| 후기 게시판 제목 | 먼저 해본 사람들의 연구참여 이야기. | 연구참여 후기 |
| 서비스 평가 척도 | 😞 🙁 😐 🙂 😀 | 별로예요 / 아쉬워요 / 보통이에요 / 좋아요 / 아주 좋아요 |
| 이메일 표시 | ✉ 주소, ✓ 이메일 인증 완료 | 주소, 이메일 인증 완료 |

브라우저 테스트가 찾는 버튼 이름(나와 연결되는 연구실 찾기, 이 연구실 알아보기, 나의 연구 가이드 보기, 후보와 메모 저장, 다른 연구실도 알아보기)은 그대로 두었다.
