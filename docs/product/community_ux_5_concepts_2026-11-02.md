# 연구실 인턴 경험 커뮤니티: UX 시안 5개

2026-11-02. [클릭 가능한 HTML 시안](community_ux_5_concepts_2026-11-02.html). 화면의 연구실·후기·수치는 모두 가상 예시다. 현재 서비스에 구현됐다는 뜻이 아니다.

## 목표와 현재 기반

사용자는 관심으로 연구실을 찾고, 과목·가이드를 본 다음 2~3곳으로 후보를 좁힌다. 후기는 ‘연구실 평가 점수’보다 **내가 실제로 무엇을 하게 될지, 무엇을 준비하면 좋을지, 어떤 질문을 확인해야 하는지**를 알려 주어야 한다.

현재 MVP에는 상세 하단의 후기 요약·목록, 전체 후기 게시판, 참여 시기·기간·했던 일·좋았던 점·아쉬운 점·추천 대상, 지도·소통/배운 점/업무량/분위기 4개 평점, 후기 작성 시트, 선배 쪽지가 있다. 참여 사실은 자기 신고다. 이 시안들은 그 기반을 재배치하거나 확장한 제안이다.

| 시안 | 사용자가 마주치는 순간 | 핵심 화면 | 장점 | 주요 부담 | 단계 |
|---|---|---|---|---|---|
| 01 상세 요약 | 연구실 내용과 과목을 본 직후 | 했던 일·도움 된 준비·미리 알 점 3개 + 원문 후기 | 기존 흐름에 가장 쉽게 결합 | 적은 후기의 과도한 요약 | MVP 우선 |
| 02 선택 체크리스트 | 지원·상담을 고민할 때 | 경험에서 나온 질문 3개와 원문 근거 | 후기를 확인 행동으로 연결 | 개인 경험을 공식 조건처럼 오인할 수 있음 | MVP 우선 |
| 03 후보 비교 | 2~3곳 저장한 뒤 | 같은 질문 축에서 후기와 정보 없음 상태 비교 | 후보 압축에 직접 도움 | 후기 수 불균형, 비교 가능한 항목 추출 | 후기 축적 후 |
| 04 나와 비슷한 경험 | 후기가 많을 때 | 참여 기간·준비 수준별 후기 정렬 | 나에게 적용 가능한 후기 찾기 | 작은 집단에서 작성자 식별 가능 | 후기 축적 후 |
| 05 질문 커뮤니티 | 후기를 읽고 질문이 남을 때 | 후기별 공개 질문·선택 답변 | 구체적 불확실성 해소 | 운영·신고·응답 부담 | 운영 체계 후 |

## 공통 후기 작성 흐름

1. 연구실은 탐색 중인 대상을 미리 선택해 준다. 참여 시기·기간을 묻는다.
2. 필수 질문은 **했던 일**, **도움 된 준비**, **다음 사람에게 한 가지** 세 가지로 한다. 선택형으로 좋았던 점·아쉬운 점·4개 평점을 펼친다.
3. 게시 전 공개 이름·참여 시기·본문을 미리 보여 주고, 개인·연락 정보와 특정 구성원을 식별할 문구가 있는지 확인한다.
4. 게시 후 수정·삭제, 신고·숨김, 운영 검토 상태를 제공한다. `참여 자기 신고`와 향후 `참여 확인 완료`를 다른 표시로 쓴다.

현재 구현의 필수 4개 평점과 여러 긴 서술 입력은 간단한 경험 공유에 부담이 될 수 있다. 위 축소 흐름은 디자인 가설이며 실제 작성 완료율을 측정해 결정한다. 연구실 평점의 평균은 후기 수가 적을 때 앞세우지 않고, **후기 개수와 시기·원문**을 먼저 제시한다. 후기마다 질문에 답한 사실과 연구실의 공식 발표를 분리한다.

## 권장 조합

초기에는 **01 상세 요약 + 02 선택 체크리스트**를 채택한다. 첫 연구실 상세 탐색의 가치를 유지하고, 소수의 후기도 ‘지원 전에 확인할 질문’으로 전환할 수 있다. 현재의 전체 후기 게시판은 원문 탐색 경로로 남긴다. 03 비교는 실제 후기가 충분히 쌓이고 후보 저장 흐름과 연결될 때, 04는 개인정보 검토와 후기량이 확보된 뒤, 05는 신고·숨김·답변 알림·작성자 중단 기능을 갖춘 뒤 검토한다.

## 검증할 사용자 과제

- 연구실 상세에서 **맡을 일, 준비할 것, 연구실에 확인할 질문**을 각각 찾을 수 있는가?
- 후기 1개와 5개인 연구실을 볼 때 정보량 차이를 이해하고, 후기 없는 연구실을 부정적으로 오해하지 않는가?
- 리뷰 작성자는 실제 경험을 2분 안에 남길 수 있는가? 공개 미리보기에서 식별될 수 있는 내용을 알아차리는가?
- 후보 비교에서 경험자의 의견과 공식 연구 정보가 혼동되지 않는가?

시연·사용성 테스트에서는 과제 성공 여부, 정보를 찾는 데 걸린 시간, 후기 작성 완료율, 근거·현재성·자기 신고 표시의 이해를 기록한다. 수치 목표는 실제 사용자 시험 전에는 확정하지 않는다.

## 근거의 적용 범위

[Baymard의 사용자 연구](https://baymard.com/research-articles/user-perception-of-product-ratings)는 평균 평점 옆의 후기 수가 판단에 중요함을 보여 준다. [평점 분포 요약 연구](https://baymard.com/research-articles/user-ratings-distribution-summary)는 리뷰가 매우 적을 때 수치 요약에 과도하게 집중시키지 말 것을 권한다. [NN/g의 제품 후기 UX 연구](https://www.nngroup.com/articles/ecommerce-product-pages/)는 작성자의 관련 맥락과 검증 표시가 신뢰 판단에 도움 된다고 보고한다. 이 연구들은 주로 상품 후기 맥락이므로 연구실·인턴 선택에 효과가 같다는 직접 증거로 취급하지 않는다. 이 문서의 시안은 본 서비스 사용자 과제로 검증할 가설이다.
