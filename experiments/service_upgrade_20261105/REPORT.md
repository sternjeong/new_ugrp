# 수업 경험 검색 고도화 실험 (2026-11-05)

## 결론과 결정

현재 서비스는 과목 제목을 문장 속에서 찾는 데 취약하다. 원문 제목을 직접 찾는 실험안은 담당 교수 연구실을 더 자주 노출했지만, 주제 탐색 문장에도 과목 가중을 줘 과목 의도를 과잉 판정한다. **실험안을 그대로 배포하지 않는다.** 수강·수업·강의·배운 경험 같은 명시적 단서가 있을 때만 원문 제목 탐지를 허용하는 후속안을 별도 개발셋에서 설계하고, 독립 시험셋에서 평가하는 것을 권장한다. 이번 실험은 그 조건부 후속안의 효과를 측정하지 않았다.

## 방법

- 기준 코드: `2092aa2`, 현행 `CuratedQueryEngine`; 데이터: `data/sunwoo/` 추천 가능 연구실 307곳 및 과목. 앱 파일을 바꾸지 않았다.
- `courses.jsonl`에서 추천 가능 담당 교수 연구실을 가진 고유 제목 과목 654개 중 무작위 200개(시드 20261105)를 뽑았다. 각 과목에 `제목 수업이 재밌었어요`, `제목에서 배운 내용을 연구에 활용하고 싶어요`를 만들어 총 400개 질의를 사용했다. 학과·학생 사용 분포를 대표하는 표본이 아니며 두 문장은 같은 과목에서 나왔다.
- 정답은 해당 과목에 명시된 추천 가능 담당 교수 연구실이다. 1명 이상이 상위 K개에 나오면 hit@K 성공이다. 다른 연구실은 관련성 미판정이며, 교수 본인의 연구 주제가 해당 수업과 적합하다고 보장하지 않는다. 목표 정답인 교수 연결은 양쪽 검색 방식이 모두 볼 수 있어 목표 누출이 있다. 따라서 이는 **담당 교수 연결을 원하는 가상의 경우에 대한 기능 진단**이다.
- Kaggle `woochuljeong/ugrp-gpu-32-gpu`의 Tesla T4에서 BAAI/bge-m3로 구절 836개를 인코딩했다. 서비스와 동일한 3,979개 문서 캐시(307개 연구실)와 내적해 연구실별 최대 유사도를 얻었다. 캐시 생성 키가 현재 프로필의 문서와 일치함을 확인했다. 현행 엔진은 이 유사도를 가짜 broker로 받아 실제 사전 검색과 순위 융합 코드를 실행했다. `best`는 빈 맵이어서 순위에는 영향을 주지 않지만 추천 근거 문구 평가는 하지 않았다.
- 비교안은 원문에 포함된 전체 과목 제목 중 가장 긴 제목을 찾고 현행 과목 연결을 과목 중심으로 융합한다. 현행 방식도 교수 연결을 이미 사용한다. 차이는 원문 제목 검출과 과목 중심 융합이며 두 효과를 분리하지 않았다. 실험계획은 [PROTOCOL.md](PROTOCOL.md)에 GPU 실행 전에 기록했다.

## 결과

| 질의 유형 | 과목 인식 현행 → 비교안 | 담당 교수 hit@1 현행 → 비교안 | 담당 교수 hit@5 현행 → 비교안 |
|---|---:|---:|---:|
| 수업 경험 200개 | 126/200 → 200/200 | 88/200 → 131/200 | 145/200 → 197/200 |
| 배운 내용 활용 200개 | 2/200 → 200/200 | 20/200 → 130/200 | 41/200 → 200/200 |
| 전체 400개 | 128/400 → 400/400 | 108/400 → 261/400 | 186/400 → 397/400 |

전체 hit@1 차이 +38.25%p(과목 단위 쌍체 bootstrap 95% 구간 +33.0~+43.25%p), hit@5 차이 +52.75%p(구간 +48.25~+57.25%p). 이는 이 합성 표본에 대한 재표집 불확실성이지 실제 학생 표본에 대한 신뢰구간이 아니다. 비교안은 질의에 정확한 제목을 의도적으로 넣었으므로 100% 인식은 일반 자연어 과목 인식률이 아니다.

### 부작용 확인: 사후 탐색

같은 200개 제목에 `연구에 관심이 있어요`를 붙인 주제 의도 통제 문장에서는 현행 엔진이 1/200개, 비교안이 200/200개를 과목 중심으로 취급한다. 비교안이 추가로 199개를 과목 중심으로 취급한 것은 주제 질의에서 원치 않는 쏠림의 위험을 보여 준다. 이 문장 역시 합성이며 쏠림이 실제 추천 관련도에 미치는 영향은 판정하지 않았다. 이 분석은 주요 실험 뒤 추가했다.

### GPU 실행 비용의 범위

노트북 기록상 모델 로딩 41.48초, 836구절 배치 인코딩 2.60초다. 단일 요청 응답 시간, 네트워크, Kaggle 대기·콜드 스타트, 모델 다운로드 전체 비용 및 운영 P95가 아니며 운영 지연 성능으로 일반화할 수 없다. 모델 이름은 기록했지만 Hugging Face revision은 고정하지 못했다.

## 재현

```bash
PYTHONPATH=. python3 experiments/service_upgrade_20261105/prepare.py
gpuhub submit experiments/service_upgrade_20261105/gpu.ipynb --accelerator NvidiaTeslaT4 --timeout-min 40
# 결과 회수 후, 저장된 이번 GPU 점수로 분석 재현:
PYTHONPATH=. python3 experiments/service_upgrade_20261105/analyze.py experiments/service_upgrade_20261105/query_scores.npz
PYTHONPATH=. python3 experiments/service_upgrade_20261105/topic_stress.py
```

GPU 입력에는 `.local/curated_doc_embeddings.npz`가 필요하다. 질의·점수·개별 순위·환경 기록은 이 폴더에 보존했다. 입력 SHA-256: 프로필 `9ebba0c5e545a4c18bc7536e516f7bf8846518183294e9e41ca373f230dde0fe`, 과목 `06f88ee3a885a42cffb1d493bdb83252a600e58c35992ded23b384c894f1e3b5`, 문서 벡터 `9627efa158c5f319b38e02a73a9bd597ff6008aa9d6cf8366071291572d4a401`.
