# 관심·연구실·수강 경험을 이용한 연구 주제 생성 예비 실험

## 결론

단일 생성 모델에 연구 질문을 만들어 달라고 하는 방식과, 연구 근거·과목의 구체적 학습 내용·학생 관심·미확인 사항을 분리하도록 지시한 방식을 비교했다. 두 번째 방식이 과목 ID를 더 자주 언급했으나 출처 ID를 사용하지 않았고, 문장 오류와 확인되지 않은 주장도 관찰됐다. **프롬프트만 강화한 결과를 서비스 가이드로 채택할 근거는 없다.** 모든 결과가 250 토큰 상한에 도달해 아래 결과는 특히 제한적이다.

## 실행

2026-11-05 사전 계획 [PROTOCOL.md](PROTOCOL.md)에 따라 현행 정제 데이터에서 연구실 세 곳의 실제 논문 초록과 과목 설명을 사용했다. 의료 센서, 로봇 손, 유기전기화학 각 사례에 대하여 관심만 변경, 과목만 변경, 선택 과목 없음, 기준의 네 합성 조건을 만들었다. 연구실과 논문은 같은 사례 안에서 고정했다. 12조건 각각에 두 프롬프트를 적용해 총 24개를 만들었다. 합성 관심이며 실제 학생의 선택은 아니다.

Kaggle run `20261105-141954-gpu`, Tesla T4, `Qwen/Qwen2.5-3B-Instruct`, 동일 모델·탐욕 디코딩, 최대 250 새 토큰이다. 모델 로딩 43.97초, 24개 순차 생성 377.11초는 실험 배치 기록으로 운영 지연 추정치가 아니다. 모델 revision은 고정하지 않았으므로 미래의 완전한 동일 재현은 보장하지 못한다. 외부 frontier API 키는 환경에서 발견되지 않았고, 공개 3B 모델의 결과는 frontier API 성능이 아니다.

## 자동 진단

| 진단 | A 일반 지시 | B 근거·추론 분리 지시 |
|---|---:|---:|
| 결과 비어 있지 않음 | 12/12 | 12/12 |
| 제공된 논문 ID 언급 | 0/12 | 0/12 |
| 수강 과목이 있는 경우 제공 과목 ID 언급 | 1/9 | 8/9 |
| 제공하지 않은 형식의 논문·과목 ID 언급 | 0/12 | 0/12 |
| 과목 없는 사례에서 과목 ID 언급 | 0/3 | 0/3 |
| 250 토큰 생성 상한 도달 | 12/12 | 12/12 |
| 관심만 바뀔 때 텍스트 변경 | 3/3 | 3/3 |
| 과목만 바뀔 때 텍스트 변경 | 3/3 | 3/3 |

이 수치는 정규식으로 ID를 문자열에서 찾은 것이다. ID가 없더라도 근거 내용을 사용할 수 있으며 ID가 있어도 연결이 맞는 것은 아니다. ID 이외의 존재하지 않는 과목명이나 허위 사실은 이 검사로 식별하지 못한다. 텍스트 변경은 관심이나 수강 경험에 적절히 반응했음을 의미하지 않는다. 프롬프트 B에 ID를 요구했지만 A에는 요구하지 않아 출처 ID 사용률은 설계 자체의 차이를 포함한다. 모든 결과가 길이 상한에 닿아 뒷부분이 잘렸으며 특히 검증·첫 단계가 출력되기 전에 끝났을 수 있다. 앞선 작성 계획의 ‘형식 유효율’은 응답 형식을 고정하지 않아 측정할 수 없다.

## 작성자의 사후 점검

- 의료 센서 A는 호흡음 논문의 내용을 ‘천식 진단 방법을 개발한 사례’로 넓혀 설명한다. 제공 초록은 천식·COPD 환자의 천명음 분류를 설명하지만 진단법 개발을 직접 뒷받침하지 않는다.
- 로봇 B는 `dexterous grasp`를 ‘다리미터적 잡기’로 잘못 표현한다. 과목 코드 EECE320을 언급해도 개념 설명의 정확성과 교육적 유용성이 보장되지 않는다.
- 화학 B는 원문의 `difluoromethylation`을 ‘다이메틸화’로 잘못 번역했다. 전문 용어 검증이 필요하다.
- 수강 선택이 없는 의료 센서 B는 과목 코드를 만들지는 않았지만 기계학습·통계학 지식을 일반적으로 언급한다. 코드 오탐률만으로 보유 역량을 추정했는지 판정할 수 없다.

위 관찰은 실험 작성자의 비블라인드 점검이다. 24개 전체에 대한 독립적 정확도·실행 가능성·학생 만족도 평가는 실시하지 못했다. [generations.json](generations.json)에 실패와 성공 후보를 모두 보존한다.

## 권장할 다음 실험

관심 질의 + 선택 연구실/논문 + 수강 과목을 입력으로 받아, (1) 논문에서 문제·방법과 해당 근거 ID를 추출, (2) 강의에서 실제 학습 개념과 근거 ID를 추출, (3) 후보 연구 질문과 시작 활동 생성, (4) 각 주장에 대해 원문을 확인하는 별도 검증, (5) 불확실 시 보류하는 파이프라인을 구성한다. 과목 경험을 숙련도·공식 요건으로 환산하지 않고 제안과 논문 사실을 분리한다.

비교는 기존 A 가이드, 하나의 모델 호출, 근거 추출+검증 파이프라인을 같은 사례에서 실행한다. 이 예비 결과만 보고 어느 방법이 우월하다고 결정하지 않는다. 개발·시험 연구실을 분리하고, 실제 학생 관심 문장과 수강 경험을 동의하에 모아 학부생·대학원생이 방식 블라인드로 연구실 근거 충실도, 관심 반영, 과목 개념 연결, 첫 활동의 실행 가능성, 허위 사실을 개별 판정한다. 원문 출처 확인이 없는 자동 생성 심사만으로 최종 채택하지 않는다.
