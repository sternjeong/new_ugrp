# 연관 과목 이유 문장 엔진 실험

연구실 상세 화면에서 과목마다 붙는 "왜 이 과목인가" 문장을 만드는 방법을 비교한다. 데이터셋이 완성되기 전에 방법론과 평가 절차를 검증해 두고, 데이터가 갖춰지면 같은 노트북을 다시 실행한다. 앱에는 아직 반영하지 않았다.

## 엔진 구조

```
(연구실, 과목) 쌍  ← bge_m3 실험의 R2 순위
  → ① 근거 선택: 연구실 주제 문장 × 과목 문장 중 가장 잘 맞는 한 쌍 (bge-reranker-v2-m3)
  → ② 문장 생성: M1~M5
  → ③ 검증: 근거 밖 단어 비율, 과장 표현
```

근거 선택과 검증은 방법과 독립적이다. 데이터가 바뀌어도 ①과 ③은 그대로 쓰고 ②만 교체해 비교할 수 있다.

| 방법 | 설명 |
|---|---|
| M1 | 개념 템플릿 (현재 앱 방식) |
| M2 | 근거 템플릿: 연구실 주제 + 과목 근거 문장 인용 |
| M3 | 키워드 템플릿: 근거 문장에서 주제와 가까운 구절 2개 |
| M4 | 로컬 LLM 생성 (기본 Qwen2.5-7B-Instruct 4비트, 근거만 사용) |
| M5 | M4 + 검증, 실패 시 M2로 대체 |

## 파일

| 경로 | 내용 |
|---|---|
| `reason_engine_v1.ipynb` | Colab(T4) 노트북. 입력: `data/`의 4개 파일 + `experiments/bge_m3/V4/rankings_v4.json` |
| `reason_engine_v2.ipynb` | v2: 근거 품질 기준(약하면 생략), 근거 한국어 번역(M2k), LLM 프롬프트·깨짐 표시 개선(M4b), 재순위 일치도 검사(M6) vs 단어 비교 검사(M5b). 같은 60쌍. 결과는 `V2/` |
| `reason_engine_v3.ipynb` | v3: 연결은 템플릿, LLM은 과목 내용 명사구만(M7), 다국어 NLI 검사(M8). 생략은 정보성 있는 근거가 없을 때만. 결과는 `V3/` |

실행 결과(`reason_results_v1.zip`)는 `V1/`에 풀어 둔다. 채점은 `reason_packet.json`만 보고 블라인드로 하며, 방법 대응표 `reason_key.json`은 채점 후에 연다.

## 평가

- 자동 지표: 평균 길이, 근거 밖 단어 비율, 과장 표현 수, 서로 다른 문장 비율
- 블라인드 채점(연구실 12곳 × 상위 5개 = 60쌍): faithful(0/1), specific·fluent·useful(1~3)

## 데이터가 완성되면 바꿀 것

- `N_LABS`, `TOP_K`를 늘려 평가 범위를 넓힌다.
- 연구실 주제 문장이 길어지면 근거 선택의 정확도가 올라가므로 M2·M3도 다시 비교한다.
- LLM은 `LLM_ID`만 바꿔 비교한다. 상업 이용 시 라이선스를 확인한다.

## v1 결과 (2026-10-09, `V1/`)

연구실 12곳 × 상위 5개 = 60쌍, 문장 237개를 블라인드로 채점했다(`V1/reason_scores.json`). 방법마다 문장 형태가 달라 완전한 블라인드는 아니다.

| 방법 | 정확(0~1) | 구체(1~3) | 자연(1~3) | 도움(1~3) | 근거 밖 단어 |
|---|---|---|---|---|---|
| M1 개념 템플릿 | 0.92 | 1.02 | 2.00 | 1.02 | 3% |
| M2 근거 인용 | 1.00 | 1.93 | 1.88 | 1.65 | 11% |
| M3 키워드 | 1.00 | 1.52 | 1.05 | 1.27 | 1% |
| M4 로컬 LLM | 0.73 | 1.98 | 2.73 | 1.90 | 52% |
| M5 LLM + 검증 | 0.98 | 1.98 | 2.07 | 1.73 | 13% |

- M4는 가장 자연스럽고 도움이 되지만 27%(16/60)가 근거에 없는 내용을 지어냈다. 예: 흡수(absorption)를 흡착(adsorption)으로 연결, 연구실 프로젝트 언급, 깨진 토큰("제어_technologies", "enrich。").
- M5 검증은 지어낸 16건 중 15건을 걸렀지만 83%를 M2로 대체했다. 영어 근거를 한국어로 바꿔 쓴 정상 문장까지 "근거 밖 단어"로 판정하기 때문이다.
- M2·M5의 품질은 근거 문장 품질에 좌우된다. "Introduction", "Course overview", "(Chapter 20-21)" 같은 근거가 뽑히면 정확하지만 쓸모가 없다.
- M3은 "을(를)", 영어 조각 때문에 부자연스럽다. M1은 짧지만 모호하고, 과목과 맞지 않는 개념을 붙이는 경우가 있다(8%).

### 다음 실험 후보
1. 근거 품질 기준: 근거 문장이 짧거나 일반적이면 다음 후보 문장을 쓰거나 이유 문장을 생략한다.
2. 언어 무관 검증: 단어 일치 대신 재순위 모델·임베딩으로 "생성 문장 ↔ 근거" 일치도를 잰다.
3. LLM 출력 정리: 한자·영어 깨짐 토큰 제거, 프롬프트에 금지 예시 추가, 한국어 강한 모델 비교.
4. M2 개선: 영어 근거를 미리 한국어로 번역하거나 요약해 인용한다.

## v2 결과 (2026-10-09, `V2/`)

같은 60쌍 중 51쌍을 평가했다(9쌍은 근거 부족으로 생략). 채점은 `V2/reason_scores.json`.

| 방법 | 정확 | 구체 | 자연 | 도움 |
|---|---|---|---|---|
| M2 영어 근거 인용 | 1.00 | 2.00 | 1.82 | 1.55 |
| M2k 한국어 근거 인용 | 0.94 | 1.94 | 1.69 | 1.55 |
| M4b 개선 LLM | 0.73 | 1.98 | 2.65 | 1.65 |
| M5b LLM + 단어 비교 검사 | 0.92 | 1.92 | 2.02 | 1.59 |
| M6 LLM + 재순위 일치도 검사 | 0.82 | 2.00 | 2.16 | 1.57 |

- 프롬프트 개선만으로는 지어내기가 줄지 않았다(M4b 부정확 27%, v1과 같음). 대부분 근거에 없는 "연결 주장"(예: 시뮬레이션 기법 → 포논 연구의 중요한 도구)이다.
- 재순위 일치도는 정확성 판정에 쓸 수 없었다. 정확한 문장 중앙값 0.975, 부정확한 문장 0.919로 거의 구분되지 않는다. M6는 부정확 14건 중 8건만 걸렀고 정확한 문장 14건을 잘못 대체했다.
- 단어 비교 검사(M5b)는 부정확 14건 중 13건을 걸렀지만 정확한 37건 중 19건도 대체했다(v1 83% → 63%).
- 번역이 새 오류를 만들었다: "Deep learning" → "Depth Learning", "NN" → "나이브 베이지안", "poly-phase" → "폴파이".
- 근거 점수 하위 15% 생략 기준은 9건 중 4건이 잘못이었다(신호 및 시스템 ↔ 레이더 신호처리 등). 재순위 점수만으로는 근거 품질을 판단하기 어렵다.
- 깨진 글자 검사는 효과가 있었다(M5b·M6 깨짐 0건).

### v3 방향
LLM에게 "연결을 설명"하게 하면 근거 밖 주장이 생긴다. 연결 부분은 템플릿이 맡고, LLM은 **과목이 가르치는 내용을 짧은 한국어 명사구로 옮기는 일만** 하게 한다(예: "PID 제어", "단백질의 구성과 구조"). 검사는 다국어 NLI 모델로 "명사구가 근거에 포함되는가"를 판정한다. 생략은 재순위 점수 대신 정보성 있는 근거 문장이 없을 때만 한다.

## v3 결과 (2026-10-11, `V3/`, Kaggle T4에서 실행)

같은 60쌍(생략 0쌍)을 Kaggle(T4, 약 6분 반)에서 돌리고 180문장을 채점했다(`V3/reason_scores.json`). 이번 채점은 이전과 **기준이 달랐다**: "직접 적용된다·필수적이다·핵심이다"처럼 근거에 없는 연결 주장은 문장 속 과목 내용이 맞아도 faithful 0으로 매겼다. 그래서 M4b 정확도(0.27)는 v2(0.73)와 직접 비교할 수 없고, **이번 표 안의 방법끼리만 비교한다.** 방법마다 문장 형태가 달라 완전한 블라인드는 아니다.

| 방법 | 정확 | 구체 | 자연 | 도움 | 부정확 건수 | 근거 밖 단어 | 깨진 글자 |
|---|---|---|---|---|---|---|---|
| M2 영어 근거 인용 | 1.00 | 1.68 | 1.88 | 1.45 | 0/60 | 11.4% | - |
| M4b LLM 자유 생성 | 0.27 | 1.73 | 2.70 | 1.47 | 44/60 | 40.1% | 6 |
| M5b LLM + 단어 비교 검사 | 0.78 | 1.70 | 2.15 | 1.48 | 13/60 | 17.5% | 19 |
| **M7 템플릿 + LLM 명사구** | 0.93 | 1.78 | 2.60 | 1.63 | 4/60 | 0.0% | 0 |
| **M8 M7 + NLI 검사** | 0.97 | 1.77 | 2.43 | 1.58 | 2/60 | 3.6% | 8 |

- LLM에게 연결을 맡기면(M4b) 60건 중 44건에서 근거에 없는 연결 주장이 나왔다. 연결을 템플릿이 맡는 M7은 4건뿐이고, 그 4건은 연결 주장이 아니라 **번역 오류**였다: solid crystals → "정상 결정체", carrier → "매개체"(2건), polarization → "극화", 그리고 명사구가 비어 "이 과목에서 을(를) 배워요"가 나온 1건.
- M7·M8은 자연스러움(2.4~2.6)이 M4b(2.7)에 근접하면서 정확도는 M2 수준에 가깝다. 도움(1.6)은 5개 중 가장 높다.
- NLI 검사(M8)는 M7 문장 16건(27%)을 M2로 대체했다(v2 단어 비교 검사는 63%). 부정확 4건 중 2건을 걸렀다. 대신 대체된 M2 문장 때문에 영어가 섞여 깨진 글자 지표가 8건으로 늘었다.
- 남은 문제: ① 번역 오류(전문용어)와 빈 명사구, ② "을(를)"·"작동 1을(를)" 같은 조사 처리, ③ 근거가 "Control Systems"·"Optimization"처럼 제목뿐인 쌍은 어떤 방법도 구체적이지 못하다(구체 평균 1.7~1.8). 연관성이 약한 쌍(예: 소재구조론 ↔ 단백질 구조 예측)에도 템플릿은 똑같이 "이어져요"라고 말한다.
- 입력 파일은 `gpuhub submit`이 `data/`와 `bge_m3/V4/rankings_v4.json`을 비공개 Kaggle 데이터셋으로 올려 연결했다.
