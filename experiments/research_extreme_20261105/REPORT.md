# 관심·연구실·수강 과목을 함께 반영하는 연구 주제 추천: 확장 실험

## 결론

12개 연구실, 32개 합성 상황에서 다섯 방식을 비교했다. 단일 생성·근거 추출형·별도 검토형은 현행 가이드보다 구체적인 과목 연결과 연구 질문을 제시하는 경향이 있었지만, **AI 심사 오류가 확인되어 이 숫자는 성능 개선의 검증된 추정치가 아니다.** 근거형과 단일 생성의 과목 연결 점수 차이는 두 심사 패널에서 +0.125와 +0.167점(2점 만점)이었고, 한쪽 구간은 0을 포함한다. 별도 검토가 생성 품질을 개선한다는 것도 사전 지표에서는 확인되지 않았다.

가장 중요한 결과는 평가 방법 자체의 한계다. 연구실/과목 연결을 실제로 제시하지 않는 현행 가이드에 AI 패널은 과목 관련 점수를 주었고, 연구실이 다른 사례를 혼동한 이유를 단 판정도 있었다. 근거형 답변 32개는 '첫 단계' 문장이 모두 같았는데 기존 AI 심사에서는 32개 모두 이 항목에 만점을 주었다. 따라서 이 실험으로 특정 방식을 운영에 적용하거나 서비스 품질이 개선됐다고 결정하지 않는다.

## 자료와 방법

- 현재 `data/sunwoo/`의 12개 서로 다른 연구실과 그 연구실에 연결된 논문 12편, 각 연구실에서 실제 선택 가능한 과목 2개를 사용했다. 과목을 바꾼 24개, 4개 연구실에서 관심을 바꾼 4개, 과목을 선택하지 않은 4개로 **32개 상황**이다. 관심은 작성자가 논문을 보고 만든 문장이므로 실제 학생 표현이나 전체 학과 분포를 대표하지 않는다. 같은 연구실의 사례는 서로 독립이 아니다.
- 논문 초록은 최대 2,200자, 과목 설명/진도는 각각 최대 1,800자를 모든 생성형에 동일하게 제공했다. 이 표본에서 초록·설명 절단은 없고 강의계획 3개 상황은 절단됐다. 표본 선정 및 독립 Luna의 입력 감사는 [scenarios.json](scenarios.json), [source_audit.json](source_audit.json)에 있다. 입력 감사의 12/12 관심 일치, 과목 24개 중 직접 12·가능 10·불명 2는 **AI 판정**이지 정답이 아니다.
- A는 현행 `CuratedCatalog.guide`, R은 영어 단어 2개 이상 겹치는 원문 문장 후보를 제시하는 규칙형, S는 단일 Luna 생성, G는 논문·과목 사실 추출 및 자체 점검을 지시한 Luna 생성, V는 G 결과를 별도 Luna가 원문 대조 후 수정한 방식이다. V의 32개 문구가 모두 수정됐다. S/G/V에는 같은 논문·과목·관심을 제공했고 같은 응답 구조를 요구했다. 현행 A는 관심과 선택 논문을 입력으로 받지 않아 다른 방법과의 비교에는 입력 차이가 함께 섞인다.
- 사용자 요청에 따라 Luna subagent를 API 대용으로 사용했으며 실제 frontier API 호출이 아니다. 모델은 한 번에 여러 사례를 처리했고, 세 심사 에이전트가 한 패널을 구성한다. 두 패널이 각각 160개 답변을 방법명 가리고 판정했다. 생성·평가가 같은 Luna 계열이고, 답변 길이와 서식으로 방식이 드러날 수 있다. 학생이나 분야 전문가의 평가는 없다. 사전 계획과 지시는 [PROTOCOL.md](PROTOCOL.md), [PROMPTS.md](PROMPTS.md)에 있다.
- 별도 Kaggle T4 실행 `20261105-145010-gpu`에서 BGE-M3로 28개 과목 선택 상황의 논문–과목 문장 최대 유사도를 계산했지만, 생성이나 심사에는 넣지 않았다. 24개의 서로 다른 과목 조합에서 Luna 입력 감사상 직접 12개 평균 0.588(범위 0.531–0.710), 가능 10개 평균 0.551(0.472–0.618), 불명 2개 평균 0.550(0.542–0.559)으로 범위가 겹쳤다. 감사 판정 자체가 AI의 의견이며 이 수치는 관련성 정확도가 아니다.

## 사전 기준 AI 판정

점수는 0/1/2, 각 연구실 내 상황을 평균한 뒤 12개 연구실을 동일 가중했다. 두 패널은 합치지 않았다. 과목이 없는 상황 4개는 과목 항목에서 제외한다.

| 방식 | 관심: 패널 1/2 | 연구실 근거: 1/2 | 과목 연결: 1/2 | 첫 단계: 1/2 | 단정 방지: 1/2 |
|---|---:|---:|---:|---:|---:|
| A 현행 | 0.42 / 0.67 | 0.54 / 1.00 | 0.67 / 1.04 | 1.04 / 1.00 | 1.71 / 1.67 |
| R 규칙형 | 1.17 / 1.06 | 1.42 / 1.40 | 1.54 / 1.32 | 1.38 / 1.06 | 2.00 / 2.00 |
| S 단일 생성 | 2.00 / 2.00 | 1.92 / 2.00 | 1.68 / 1.67 | 2.00 / 2.00 | 2.00 / 2.00 |
| G 근거·자체 점검 | 2.00 / 1.92 | 2.00 / 1.92 | 1.81 / 1.83 | 2.00 / 1.92 | 2.00 / 2.00 |
| V 별도 검토 | 1.98 / 1.96 | 1.98 / 1.96 | 1.76 / 1.71 | 1.98 / 1.96 | 2.00 / 2.00 |

사전 주요 대비인 과목 연결 G−S는 패널 1에서 +0.125 [0.000, +0.292], 패널 2에서 +0.167 [−0.042, +0.389]이었다. V−G는 −0.042 [−0.167, +0.083], −0.125 [−0.250, 0.000]이었다. 대괄호는 12개 연구실을 단위로 한 짝차이 bootstrap 95% 구간이다. 편의 표본의 재표본이며 실제 학생 모집단에 대한 신뢰구간이 아니다. 단정 방지는 R/S/G/V 모든 답변에 양 패널이 만점을 주어 비교 구분력이 없었다. **이 결과를 무오류라는 뜻으로 해석하면 안 된다.**

평가자 간 과목 점수 일치는 75/140, 이차 가중 카파 0.41이다. 연구실 항목 일치는 109/160, 카파 0.55였다. 한 평가자 집합에서 `case_06_course2`의 현행 답변을 아연 증발기 연구로 잘못 설명했다. 이는 실제 해당 맥락인 소형 언어모델·로봇과 다르다. 해당 사례 전체를 모든 방법에서 제외한 사후 민감도 결과도 [analysis_excluding_case06course2.json](analysis_excluding_case06course2.json)에 보존했다. 원본 점수는 수정하지 않았다. 추가 AI 감사는 이 오류를 찾았지만 다른 패널의 정상적인 설명에도 같은 오류가 있다고 잘못 표시했으므로 **감사 모델까지 자동 정답으로 취급하지 않는다.**

## 채점 신뢰도 검토와 사후 엄격 평가

현행 A는 코드를 보면 선택 과목의 구체 학습 내용과 연구를 연결하지 않는다. 그런데 과목 선택 28개에 대해 패널 1은 18개에 1점, 패널 2는 19개에 1~2점을 주었다. 포괄적인 '직접 확인' 문구를 실제 연결로 과대평가했을 가능성이 크다. 또한 G의 첫 단계는 32개 모두 동일한 일반 문장인데 두 패널은 G에 각각 32/32, 29/32 만점을 주었다. 이 때문에 앞 표를 모델 성능의 객관적 근거로 쓰면 안 된다.

이를 확인한 뒤 세 Luna에게 **사후에** 더 엄격한 기준(과목명/일반 확인 문구만 있으면 0, 일반적인 논문 요약 단계는 1)을 주어 다시 채점했다. 이는 사전 결정 지표가 아니고 단일 패널이다.

| 방식 | 엄격 과목 연결 평균 /2 | 엄격 첫 단계 평균 /2 | 첫 단계 고유 문구 수 |
|---|---:|---:|---:|
| A 현행 | 0.19 | 1.00 | 해당 없음 |
| R 규칙형 | 0.38 | 1.00 | 해당 없음 |
| S 단일 생성 | 1.19 | 1.08 | 6/32 |
| G 근거·자체 점검 | 1.26 | 1.04 | 1/32 |
| V 별도 검토 | 1.26 | 1.69 | 9/32 |

엄격 평가에서도 현행 A에 구체적 과목 연결 만점이 1건 부여됐고, G의 동일한 첫 단계 중 1건은 구체적이라는 2점을 받았다. 따라서 엄격 평가도 완전하지 않다. 수강 과목이 없는 사례 한 건을 평가자가 `course=0`으로 잘못 채점해 분석 시 null로만 보정했으며 원본과 보정 기록을 남겼다. V−G의 엄격 첫 단계 차이는 +0.646 [0.396, 0.875]였으나, **사후에 기준을 정하고 동일 Luna 계열이 채점한 결과**라 확인적 효과로 해석할 수 없다.

사후 단일 Luna 패널의 좌우 블라인드 직접 비교에서는 G 대 S가 22승·3패·7동점, V 대 G가 14승·2패·16동점이었다(각 32쌍). 같은 연구실의 사례가 반복되고 별도 사람 심사는 없으며, 사전 다차원 점수와 다른 평가 질문이므로 두 결과를 합쳐 우월성을 입증할 수 없다. 원문과 이유는 [pairwise_analysis.json](pairwise_analysis.json)에 있다.

## 사례와 권고

`case_07_course1`에서 V는 아연–요오드 전지 논문 W7204837857의 전류밀도·사이클 수·용량·효율을 정리하고, 수강한 BATT524의 전극 과정·전자 전달·물질 전달과 연결해 볼 것을 제안했다. 초록에 없는 구리 미사용 대조군이나 측정 조건은 논문 본문에서 확인해야 한다고 분리했다. 이는 해당 논문의 실제 내용을 지어낸 주제와 혼동하지 않는 예다. 반대로 과목과 논문이 약하게 연결된 경우 직접 관계를 단정하지 않고 보류해야 한다.

다음 후보는 선택된 논문·수업 원문을 먼저 구조화하고, 연구 질문을 생성한 뒤 **별도 검증 호출**에서 주장별 근거 문장을 확인하며 과목 연결이 약하면 보류하는 방식이다. 그러나 V에서 개선됐다는 증거가 확보된 것은 아니다. 먼저 단일 생성과 별도 검증의 입력·출력·호출 예산을 통제하고, 실제 학생 질의와 해당 분야 학생·대학원생의 독립 판정으로 관심 반영, 연구실 사실, 과목 지식 연결, 구체적 시작 행동, 거짓 주장과 유용성을 개별 평가해야 한다. 심사자에게 근거 ID뿐 아니라 실제 원문 구절을 제공하고, AI 점수와 사람 점수를 따로 보고한다.

## 재현과 범위

입력·전체 결과·두 심사 패널·사후 엄격/좌우 비교 원본은 이 폴더에 있다. `PYTHONPATH=. python3 experiments/research_extreme_20261105/prepare.py`, `make_gpu.py`, Kaggle `gpuhub submit .../gpu.ipynb`, `PYTHONPATH=. python3 .../make_packets.py`, `python3 .../analyze.py`, `python3 .../quality_audit.py`, `python3 .../analyze_strict.py`, `python3 .../analyze_pairwise.py`로 자료와 지표 계산을 재현할 수 있다. Luna 생성·평가는 현재 기록된 결과를 재분석할 수 있지만 재호출 시 같다고 보장하지 않는다. 과거 기록의 데이터에는 개인정보가 아닌 공개 논문·강의 설명과 합성 질의만 사용했다. 운영 서비스와 `app_profiles.jsonl`은 수정하지 않았다.
