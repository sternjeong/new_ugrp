# 사전 계획: 운영 엔진 vs 팀원 vectorRAG (feat/proto) 자연어-연구실 탐색 비교 (2026-11-09)

실행 전에 작성했다. 결과를 본 뒤 바꾼 것은 REPORT.md에 따로 적는다.

## 비교 대상 (각자의 실제 코드를 그대로 실행)
- **H 운영 엔진** (`service-meetings-zoom`, `CuratedQueryEngine`): 문장별 해석 → 사전 검색 + BGE-M3 구절 유사도 + 과목 연결 → RRF. 피드백 재정렬은 끄고 비교한다(데이터 없음).
- **V 팀원 vectorRAG** (`ugrp-hesse/feat/proto` 7087b4a, `curri/rag`): 연구실 조각 9,824개 전수 BGE-M3 코사인 → 교수별 상위 조각 가중합(1, 0.3, 0.15) → 공동 연구실 묶기 → 상대 점수 하한.
- 두 시스템 모두 같은 추천 가능 연구실 307곳을 쓴다. 임베딩은 같은 Kaggle 작업에서 `BAAI/bge-m3`(sentence-transformers, 정규화)로 계산한다. 팀원 코드는 Ollama bge-m3로 설계됐으므로 벡터 값은 소폭 다를 수 있다.

## 질의
| 묶음 | 수 | 출처 | 누구에게 유리할 수 있나 |
|---|---:|---|---|
| T | 30 (패널 12) | 팀원 평가셋 `data/eval/advisor_queries.jsonl`, 정답 연구실 포함 | V |
| M | 10 | 내 진단 질의 중 검색 의도 | H |
| B | 20 | 두 시스템을 모르는 Sonnet이 학과 목록과 유형 비율만 보고 작성 | 없음 |

패널용 T 12개는 질의 id 순서로 고른 고정 표본이다(앞 12개).

## 평가
1. **Sonnet 판정 패널 (주 지표):** 질의마다 독립 프로세스 5개.
   - 두 엔진 상위 10곳의 합집합 + 무관 대조군 2곳을 섞어, 엔진 정보 없이 같은 형식의 연구실 카드로 제시한다. 판정자마다 순서를 섞는다.
   - 연구실마다 관련도 0~3: 0 무관, 1 약간 겹침, 2 관련 있음, 3 매우 적합. 학생이 싫다고 한 주제가 중심이면 낮게 준다.
   - 질의·연구실별 5명 평균을 이득으로 쓴다.
   - **주 지표: nDCG@10** (합집합을 정답 풀로 사용). 보조: P@5(평균 2 이상 비율), 상위 5 무관률(평균 1 미만), MRR(첫 2 이상).
   - 차이는 질의 단위 bootstrap 95% 구간과 승/무/패로 보고한다. 묶음별로도 본다.
   - 판정 신뢰도: Krippendorff α, 대조군 평균 점수.
2. **정답 기반 지표:** T 30개의 정답 연구실로 hit@1, hit@5, MRR, recall@5.
3. **운영 비용:** 질의당 CPU 시간, 메모리, 필요 자원.

## 판정 규칙
nDCG@10 차이의 95% 구간이 0을 포함하지 않으면 높은 쪽을 우수로 본다. 포함하면 "차이를 확인하지 못함"으로 보고한다. 묶음별 결과가 엇갈리면 그대로 적는다.

## 알려진 한계
- 판정자는 사람이 아니라 Sonnet이다. 같은 모델 5회 실행이라 공통 편향이 남는다.
- 합집합만 판정하므로 두 엔진 모두 놓친 연구실은 평가되지 않는다.
- 내가 H의 개발자이고 이 실험의 작성자다. 그래서 질의 B는 Sonnet이 만들고 T는 팀원 것을 그대로 쓴다.
