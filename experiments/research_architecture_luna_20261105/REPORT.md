# 관심·연구실·수강 과목 기반 연구 주제 비교 실험

## 관찰과 판단

현행 가이드, Luna 단일 생성, Luna 근거 추출·자체 점검형을 6개 합성 사례에 비교했다. 두 별도 Luna 평가자의 과목 연결 점수는 각각 현행 0.00/2, 단일 1.17·1.50/2, 근거형 1.50·1.83/2였다. 현행은 선택한 과목의 내용을 주제와 연결하지 않는 것이 코드에서 확인된다. 이 표본에서 근거형은 더 구체적인 연결을 만들었으나, **실제 학생이나 전문가가 평가한 것이 아니며 이 수치로 서비스 품질 향상이 입증되지는 않았다.**

## 비교 방법

- 현행 `sunwoo`의 논문 초록·강의 설명과 작성자 합성 관심을 사용했다. 연구실 3곳(의료 센서·로봇·유기화학)에 각각 수강 과목만 다른 2개 상황이다. 6개 과목 모두 해당 연구실의 현행 선택 가능 목록에 있다. 세 연구실 내 쌍은 독립 사례가 아니다.
- **현행:** 실제 `CuratedCatalog.guide`에 같은 수강 과목을 넘기고 두 열의 제목·설명·단계·과목·연구실 근거를 렌더링했다. 현행은 관심 문장이나 선택 논문을 입력으로 받지 않는다.
- **단일 생성:** Luna에 같은 논문 초록·관심·과목을 주고 주제와 이유·첫 단계를 요청했다.
- **근거·자체 점검형:** 별도 Luna에 같은 자료를 주고 논문 사실과 과목 내용을 분리하고 근거를 표시한 뒤 제안·불확실성을 점검하도록 요청했다. **별도 모델 호출을 하는 실제 파이프라인이 아니라 한 에이전트 실행 내부의 단계 지시**다.
- 답변 18개를 순서를 섞고 방법명을 지운 후 별개 Luna 두 명이 각각 다섯 항목을 0/1/2점으로 채점했다. 심사자들에게는 현행 가이드가 사용하는 연구실 원문도 제공했다. 생성 에이전트에게는 선택된 논문 초록을 제공했다. 현행과 생성형은 이용하는 정보와 답변 길이가 다르므로 점수 차이는 여러 요인이 섞여 있고, 형식으로 방법을 짐작할 수도 있다.
- 사용자가 요청한 Luna subagent는 API 호출 대용이며 실제 frontier API나 실제 사용자 실험이 아니다. 생성과 심사에 같은 계열 모델이 쓰여 편향이 공유될 수 있다.

## 결과

각 값은 여섯 사례의 평균이며 최대 2점이다. 평가자 결과는 합치지 않았다.

| 지표 | 현행: 평가자 1 / 2 | 단일 생성: 평가자 1 / 2 | 근거형: 평가자 1 / 2 |
|---|---:|---:|---:|
| 관심 반영 | 1.00 / 1.00 | 2.00 / 2.00 | 2.00 / 2.00 |
| 연구실 내용 | 0.67 / 1.00 | 1.67 / 2.00 | 1.67 / 2.00 |
| 선택 과목 내용 연결 | 0.00 / 0.00 | 1.17 / 1.50 | 1.50 / 1.83 |
| 첫 단계 | 1.00 / 1.00 | 2.00 / 2.00 | 2.00 / 2.00 |
| 불확실성·부당한 단정 방지 | 1.00 / 2.00 | 1.17 / 1.17 | 2.00 / 2.00 |

18개 답변에 대한 두 평가자의 점수 완전 일치 건수는 관심 18/18, 연구실 12/18, 과목 14/18, 첫 단계 18/18, 단정 방지 12/18이다. 한 평가자는 선택 논문이 폐음 연구를 보여 주는데도 추가로 주어진 연구실 소개 문구에 같은 내용이 없다는 이유를 들어 해당 연구실 점수를 1점으로 적었다. 이는 심사 과정도 불완전함을 보여 주며 서로 다른 평가자 점수를 합쳐 정답으로 삼지 않았다. 여섯 사례는 세 연구실에서 만든 편의 표본이므로 신뢰구간이나 인과 효과를 주장하지 않는다.

근거형이 출력한 논문 ID와 과목 ID는 각각 6/6이 입력과 일치했다. 단일 생성은 ID 사용을 요구하지 않았고 0/6이었다. 이는 입력에 존재하는 ID의 문자열 일치 확인이지 해당 논문이 주장을 뒷받침하는지 검증한 것이 아니다. 두 생성 결과에서 제공되지 않은 ID는 정규식으로 검출되지 않았다. 해당 정규식은 `W`, CSED·EECE·CHEM·CHEB·DISU 코드만 탐지하며 일반 문장·과목명의 허위 주장은 확인하지 못한다. 원문 직접 인용부호는 출력에 없어 문장 일치 검사는 해당되지 않는다.

## 실제 예와 실패

의료 센서 사례에서 근거형은 논문 W4406560002의 호흡음·천명 분류와 과목 EECE454의 SVM·신경망 학습을 연결해 공개 또는 사용 승인을 받은 자료에서 분류기를 비교하는 질문을 제안했다. 데이터와 라벨 접근은 확인되지 않았다고 별도로 밝혔다. 이는 **논문에 실린 실험이라는 주장 대신 서비스의 탐색 제안**이다.

반면 로봇 사례에서 근거형이 기계학습 과목을 언급해도 그 과목 내용이 접촉 기반 파지 문제에 구체적으로 어떻게 적용되는지 평가자 둘 모두 부분적이라고 판단했다. 의료 센서에서 반도체 소자 과목을 선택한 경우에도 해당 과목과 폐음 분석의 직접 연결은 불확실하다. 관계가 약한 과목까지 억지로 활용 지식으로 만들지 말고 ‘연결 확인 필요’로 표시해야 한다.

## 권고와 후속 검증

근거 추출→후보 생성→검증이라는 방향을 다음 프로토타입의 후보로 유지하되 즉시 운영에 반영하지 않는다. 별도 호출로 분리된 검증 단계, 출처 구절의 존재·일치 검사, 선택 과목이 부적합할 때 연결을 거절하는 규칙, 논문에 없는 프로젝트·자원 접근·숙련도 주장 필터를 구현해 비교해야 한다. 단일 호출과 동일한 입력·출력 길이 조건에서 각각의 기여를 분리하고 실제 학생 질의와 학부생·대학원생 블라인드 판정을 모아야 한다. 강의계획 일부와 논문 초록이 길이 제한으로 잘려 있으므로 원문 확보율도 실험에서 따로 측정해야 한다.
